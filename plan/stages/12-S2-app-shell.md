# S2 — 앱 뼈대: GPUI, 키맵, 모드, 명령 팔레트, 설정

목표: 아직 노트를 그리지 않아도, 창이 뜨고 메뉴·트랜스포트·트랙 목록·인스펙터·상태줄·명령 팔레트·설정이 있고, 키맵 엔진이 Action을 발화한다. S1의 스케줄러를 트랜스포트 버튼으로 돌린다.

관련 REQ: 4 P1·P2·P8, 5.5, 5.11(Tab의 Normal·설정 부분), 7.1, 7.2, 7.3, 7.5, 7.6, 9.4
선행: S1

## Task 목록

### S2-T1 GPUI 앱과 창 모델

- 범위: gpui-kit 의존 추가, 문서 기반 창 모델(창 하나 = 프로젝트 하나, 여러 창), `Root`·`Dock`·`Resizable`로 7.1 레이아웃 골격(메뉴바·트랜스포트·트랙 목록·메인 빈 영역·하단 영역·상태줄·인스펙터), 다크·라이트 `Theme`, 12색 트랙 팔레트 토큰.
- 테스트 게이트: 빌드 및 창 생성 UI 테스트. 패널 접기·크기 조절 상태가 설정에 저장·복원.
- 리뷰 초점: 모델 상태가 GPUI `Entity`에 어떻게 담기는가 — `core::Project`를 직접 노출하지 않고 문서 엔티티가 undo 엔진을 거쳐 변경하는가.

### S2-T2 키맵 엔진

- 범위: KM-1·2·5·6·7·11·12. (컨텍스트, 키 시퀀스) → Action 매핑, 프리셋 `default`·`vim`, 사용자 오버라이드 레이어, 멀티키 시퀀스·카운트 접두(엔진은 지원, default 프리셋은 쓰지 않음), 물리 키 매칭(가사 모드·텍스트 필드 예외 훅), `Cmd` 표준 단축키의 프리셋 불변, JSON 로드·핫리로드·오류 위치 보고. Action 정의는 `actions!` 매크로로 한 곳에.
- 테스트 게이트: 키맵 JSON 스냅샷(REQ 7.3 예시). 한/영 전환 상태에서 같은 물리 키가 같은 Action. 충돌·접두 충돌 감지 단위 테스트. 프리셋 전환 후 오버라이드 유지.
- 리뷰 초점: 컨텍스트 매칭 우선순위가 문서화·테스트되었는가(`Normal > Arrangement`가 `Normal`보다 우선).

### S2-T3 모드 FSM과 Enter/Esc/Tab 규약

- 범위: REQ 5.5. Normal(피아노롤/배치 뷰)·Step·Sequence·Play·AI 상태, `Enter` 들어가기, `Esc` 한 단계씩 나가기(고스트→선택→모드→피아노롤→배치 뷰), `Ctrl+Tab` 순환, 상태줄 모드 표시와 클릭 메뉴. 각 모드의 실제 동작은 이후 단계가 채운다(여기서는 상태 전이와 표시만).
- 테스트 게이트: 전이 표를 테이블 테스트로. `Esc` 연타가 어느 상태에서든 배치 뷰·선택 없음으로 수렴.

### S2-T4 명령 팔레트와 메뉴바

- 범위: UI-2·UI-11·KM-13·7.6. 모든 Action이 이름·설명·현재 단축키와 함께 팔레트에 나옴, `:`도 팔레트, 7.6의 메뉴 7개와 항목, 메뉴 항목 = Action 1:1(자동 생성).
- 테스트 게이트: 등록된 Action 수 = 팔레트 항목 수 = 메뉴 항목 수 + 메뉴에 없다고 명시한 Action 수(검사 테스트). 단축키 표시가 현재 키맵을 반영.

### S2-T5 트랜스포트·트랙 목록·인스펙터·상태줄

- 범위: TRN-1·TRN-4, UI-5·UI-12, SEQ-7·SEQ-8 UI, 7.6의 해당 행. 재생·정지·녹음 버튼(녹음은 S5까지 비활성), 템포·박자표·조성 필드, 메트로놈 토글, `AI✦` 토글(S7까지 비활성), 포트 드롭다운, 트랙 목록(M/S, 포트·채널 표시, `+`), 인스펙터(이름·색·포트·채널·뱅크·프로그램·기본 벨로시티·가사 언어·테스트 버튼), 상태줄.
- 테스트 게이트: 트랜스포트 버튼이 S1 스케줄러를 실제로 돌린다(루프백에서 Note 수신). 채널 충돌 경고가 뜬다. 인스펙터 편집이 undo 단위로 들어간다.
- 이월(S0-T6 리뷰 2 제안 4): 포트·조성을 바꿀 때 `.ksq` 모르는 키 처리. 결정 요청 `docs/decisions/2026-10-12-ksq-unknown-keys-on-value-change.md`.
- 이월(S1-T1·S1-T2): 앱은 시작할 때 CoreMIDI 관련 호출 가운데 `MidiClient::new`를 가장 먼저 부른다(알림 전달 조건, `PortWatcher::start`가 아니면 `NotificationsUnavailable`). `MidiClient` 핸들은 하나를 만들어 복제해 쓴다. MIDI 서버 재시작을 알아차리면(`VirtualOutput::is_registered`가 거짓) 모든 가상 포트에 `reregister`를 부르고 상태줄에 알린다. `PortWatcher` 이벤트로 상태줄 표시와 `Reconnector` 재연결을 하고, 열려 있는 `OsOutput`은 `is_present`로 확인한다. `PortWatcher::start`는 탐침 때문에 약 0.25초(최악 2초) 블로킹하므로 메인 스레드가 아닌 곳에서 부르고, 서버 재시작 뒤에는 감시자도 다시 시작한다. `suggest_mapping`의 `Virtual` 제안은 서로 겹치거나 16개를 넘을 수 있으므로 UI에서 만들기 전에 확인한다(S1-T2 리뷰 2 제안 3, 6, 8).

### S2-T6 설정 화면과 키맵 편집기

- 범위: KM-3·4·8·9·10, 설정 > 입력·MIDI 출력·메트로놈·키맵·AI(AI 탭은 비활성 플레이스홀더). press-to-bind, 충돌 시트, 프리셋 전환, 내보내기·가져오기, `?` 오버레이.
- 테스트 게이트: 키맵 편집기를 키보드만으로 끝까지 조작하는 UI 테스트. 가져온 키맵의 충돌이 적용 전에 잡힘.
- 이월(S0-T4 리뷰 3 제안 3): undo 히스토리 메모리 상한의 기본값과 정책을 정한다. 상한이 있으면 `Document::undo`가 성공하면서 가장 오래된 undo 단위를 버릴 수 있다(되돌리는 쪽은 작고 다시 하는 쪽이 큰 편집: 녹음 테이크, 붙여넣기). REQ EDT-1 「무제한」과의 관계를 결정 요청으로 다룬다.

### S2-T7 저장·열기·복구

- 범위: IO-5, 7.5의 파일 단축키, 자동 저장본(`~/Library/Application Support/KeyScore/autosave/<경로 해시>.ksq`, 30 s), 크래시 후 복구 제안, 저장 안 된 변경의 닫기 시트, 최근 파일.
- 테스트 게이트: 저장 중 kill 시뮬레이션 후 원본 보존. 자동 저장본이 프로젝트 폴더에 생기지 않음.
- 이월(S0-T6 리뷰 1 제안 6): 상위 `format_version` 파일의 저장 정책. 결정 요청 `docs/decisions/2026-10-12-ksq-newer-version-save.md`.
- 이월(S0-T6 리뷰 2 제안 6): 읽기 전용(예: 0444) 파일에 저장하면 지금은 경고 없이 성공하고 권한이 유지된다. 저장 거부 또는 확인을 저장 흐름에서 정한다.
- 이월(S1-T6, 결정 `docs/decisions/2026-10-16-s1-t6-review-limit.md`): SMF 가져오기·내보내기 메뉴를 붙일 때 다음을 정한다.
  - 리뷰 4 제안 1: 가사 전용 트랙 붙이기 비용의 「맞은 수」 항은 (곡 트랙 × 가사 트랙 × 공유 틱)까지 자란다. 곡 트랙 8000 × 가사 트랙 500에서 릴리스 0.39 s. 가져오기를 백그라운드에서 돌리고 진행 표시를 둘지 정한다.
  - 리뷰 4 제안 2와 리뷰 2 제안 6: 곡 트랙이 남지 않는 파일의 가사, 노트 없는 모델 트랙은 경고 없이 사라진다. 가져오기·내보내기 결과 요약에 버린 항목을 알릴지 정한다.
  - 곡 길이 상한(`MAX_SONG_TICKS`)을 넘는 SMF·프로젝트의 `TooLong` 오류 문구.
