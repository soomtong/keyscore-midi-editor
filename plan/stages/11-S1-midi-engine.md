# S1 — MIDI 엔진: 가상 포트, 스케줄러, SMF

목표: 모델의 클립을 외부 신디로 정확한 타이밍에 내보낸다. 이 단계가 끝나면 CLI로 `.ksq`를 재생해 Surge XT에서 소리가 난다.

관련 REQ: 4 P4·P5·P7, 6.3, 6.4, 6.5 M2-1, 6.6 IO-2, 8.1, 8.4, 9.2, 9.3
선행: S0

## Task 목록

### S1-T1 CoreMIDI 가상 출력 포트

- 범위: OUT-1·OUT-2. 앱 시작 시 가상 소스 등록(MIDI 1.0 프로토콜), 여러 개(최대 16), 이름 변경, 종료 시 해제. `MidiPort` 트레이트(가상·OS 포트 공통).
- 결정 분기: SP-3 결과에 따라 `coremidi` 크레이트(A) 또는 `core-midi-sys` 직접 호출(B).
- 테스트 게이트: 통합 테스트 — 가상 소스를 만들고 같은 프로세스의 수신 클라이언트가 그것을 본다. 프로세스 종료 후 포트가 남지 않음(수동 확인 항목).
- 리뷰 초점: FFI 경계의 unsafe 범위가 최소인가. 핸들 수명이 RAII로 묶였는가.

### S1-T2 OS 포트 열거·핫플러그·재연결

- 범위: OUT-3·OUT-8. 포트 목록, 변화 콜백, 이름 기반 자동 재연결, 프로젝트에 저장된 포트 이름의 대체 매핑 제안(데이터 구조만; UI는 S2).
- 테스트 게이트: 포트 소멸·재등장 시뮬레이션(가상 포트를 만들고 지우는 테스트 앱)에서 콜백 순서와 재연결 확인.
- 이월(S1-T1 리뷰 2 제안 5): 프로세스 CoreMIDI 클라이언트는 해제하지 않고 캐시한다. MIDI 서버가 재시작하면(`kMIDIMsgSetupChanged`류 알림, 서버 소멸) 캐시된 핸들을 다시 만들고 가상 포트를 재등록하는 경로를 이 Task의 알림 처리에서 다룬다. (S1-T2 처리: 서버 소멸 오류면 캐시를 버려 다시 만들고, `VirtualOutput::is_registered`·`reregister`를 제공한다. 서버 재시작을 알아차려 모든 포트에 `reregister`를 부르는 일은 포트를 소유한 앱이 하므로 S2-T*로 이월한다.)
- 이월(S1-T1 리뷰 3 제안 6): `keyscore-midi` 통합 테스트가 드물게(구현자 약 80회 중 1회, 리뷰어 32회 중 1회) 한 바이너리 전체가 함께 실패했다. 출력을 남기지 못했다. MIDI 서버가 내려가거나 다시 뜨는 순간으로 추정한다. 이 Task의 알림 처리(서버 재시작 감지)를 만들 때 재현과 원인을 확인하고, 실패 시 출력이 남도록 반복 실행 스크립트를 둔다. S1-T1 리뷰 4가 출력을 잡았다: 유휴 뒤 첫 MIDI 사용 바이너리에서 `MIDIClientCreate`가 `-304`를 3초 넘게 돌려줬다. 재시도 한도를 10초로 늘렸으므로, 여기서는 그 한도로 충분한지와 서버 재기동 감지를 확인한다. 또 재시도 루프가 `PROCESS_CLIENT` 잠금을 쥔 채 잠들어, 서버가 오래 응답하지 않으면 첫 생성을 동시에 부른 스레드들이 차례로 최대 10초씩 막힌다(S1-T1 리뷰 5 제안 2). 실패를 잠시 기억해 뒤 호출이 바로 실패하게 하는 방식 등을 함께 정한다.

### S1-T3 MIDI 1.0 인코딩과 다운스케일

- 범위: 채널 보이스(Note On/Off, Program Change, Bank Select, CC, Pitch Bend 14비트), 시스템 리얼타임(Clock, Start/Stop/Continue, SPP), All Notes Off/All Sound Off. 16비트 벨로시티·32비트 CC → 7비트 변환은 MIDI 2.0 명세의 변환 규칙(M2-1). Running status는 쓰지 않는다(수신 호환 우선).
- 테스트 게이트: 변환 규칙 표(명세의 예시값)를 테이블 테스트로. 벨로시티 0은 Note Off로.
- 해석(S1-T3 계획, 리뷰 1 제안 2): 「벨로시티 0은 Note Off로」는 MIDI 1.0의 의미(벨로시티 0인 Note On = Note Off)다. 모델의 Note On은 REQ M2-1이 따르라는 MIDI 2.0 변환 규칙대로 7비트 결과가 0이면 1로 보내고, 노트를 끄는 것은 Note Off(0x8n)로 보낸다. S1-T6(SMF)은 가져올 때 벨로시티 0인 Note On을 Note Off로 읽는다.
- 리뷰 초점: 상위 비트 절삭을 쓴 곳이 없는가.
- 이월(S1-T1 리뷰 1 제안 6, 리뷰 2 제안 6): `MidiPort::send`는 워드 수만 검사하고 UMP 메시지 타입은 거르지 않는다. MIDI 1.0 소스가 전달하지 않는 타입(0x0 NOOP, 0x4–0xF 등)은 CoreMIDI가 조용히 버린다. 인코더가 0x1·0x2·0x3 타입만 만들도록 하고, 그 밖의 타입을 송신 경로로 넘기지 않음을 테스트한다.

### S1-T4 스케줄러 스레드

- 범위: REQ 9.2·9.3·OUT-7. 실시간 우선순위 스레드, 락 없는 SPSC 링버퍼로 UI와 통신, 모델 스냅샷(불변 Arc)을 받아 틱→시각 변환, CoreMIDI 타임스탬프로 수 ms 앞서 예약 송신, 재생/정지/위치 이동/루프, 재생 시작 시 프로그램 체인지·CC chase(CTL-6), 패닉(OUT-6), MIDI Clock(OUT-5, 기본 끔).
- 테스트 게이트: 루프백 통합 테스트 — NF-1(키→송신 ≤ 3 ms p99: 여기서는 「명령 큐 투입→송신」으로 측정), NF-3(지터 ≤ 0.5 ms p99, 10분 축약판; 1시간판은 야간 CI), NF-4(드리프트). 디버그 빌드에서 `assert_no_alloc`로 스케줄러 루프의 할당 0 확인. 테스트 결과 수치를 보고서에 적는다.
- 리뷰 초점: 스케줄러 루프 안의 모든 호출을 따라가 할당·락·로그·시스템 콜을 찾는다. 하나라도 있으면 차단. 재생 중 모델이 바뀔 때(TRN-3) 스냅샷 교체가 원자적인가.
- 이월(S1-T3 리뷰 2 제안 5): 스케줄러는 `Midi1Message::ump(Group)`로 만든 워드만 `MidiPort::send`에 넘긴다. 날 `u32`를 직접 만들지 않아 그룹·타입 보장이 송신 경로 끝까지 이어지게 한다.

### S1-T5 메트로놈과 미리듣기

- 범위: MET-1~3(포트·채널·노트 설정, 녹음 중 강제 켬은 플래그로), PRE-1(단발 Note On/Off, 기본 200 ms). 시각 메트로놈용 박자 이벤트를 UI로 보내는 채널.
- 테스트 게이트: 메트로놈 클릭이 틱 그리드 정확히에 송신됨(루프백). 미리듣기 노트가 Note Off 없이 남지 않음(패닉 없이 200 ms 뒤 꺼짐).

### S1-T6 SMF 입출력

- 범위: IO-2·SEQ-9·LYR-6·CTL-10. Type 0/1 읽기·쓰기, PPQ 재배율, 채널별/트랙별 트랙 생성, 노트 구간을 마디 단위 클립으로, Lyric 메타(0x05) 왕복, CC 이벤트 ↔ 포인트 열, 템포·박자표 변화 보존.
- 테스트 게이트: 공개 SMF 샘플 10개 읽기 → 쓰기 → 읽기 동일(이벤트 집합 비교). 가사가 있는 샘플 왕복. 벨로시티·CC 보존. 벨로시티 0인 Note On을 Note Off로 읽는 사례.
- 이월(S1-T3 리뷰 3 제안 2): 모델에 벤드를 저장할 때는 부호 없는 32비트(가운데 0x8000_0000)로 둔다. 인코더 `pitch_bend`와 S6-T1의 레인 변환이 같은 표현을 쓴다.
- 리뷰 초점: 악의적 SMF(길이 필드 거짓, 트랙 수 과다)에서 패닉·OOM 없이 `Err`.
- 이월(S1-T3 리뷰 2 제안 2): 가져올 때 벨로시티 0인 Note On은 Note Off로 읽는다(MIDI 1.0 의미, S1-T3 절의 해석). 테스트 게이트에 그 사례를 더한다.

### S1-T7 `ksq-cli play`

- 범위: CLI에서 `.ksq`를 지정 포트로 재생. 메트로놈 옵션. 스케줄러의 첫 실사용.
- 테스트 게이트(수동): Surge XT가 `KeyScore Out`을 입력으로 잡고 픽스처 1곡을 끝까지 재생. 패닉 명령으로 걸린 노트가 없음.
