목표: 처음 설치한 사람이 10분 안에 소리를 내고, 비기능 요구사항이 수치로 확인되며, 서명된 .app이 Homebrew로 배포된다. M4 게이트.

관련 REQ: 7.7, 8절 전체, 2절의 배포·CI·텔레메트리·언어 결정, 11절
선행: S7

## Task 목록

### S8-T1 온보딩

- 범위: REQ 7.7 세 단계, 추천 신디 링크, 테스트 노트·체크리스트, 보정 마법사 연결, 「다음 단계」 카드, 도움말에서 재실행, SP-4 결과에 따른 리스너 표시 또는 안내만.
- 테스트 게이트: UI 테스트 — 온보딩을 키보드만으로 끝까지. 건너뛰기 후 재실행.
- 수동 게이트: 앱을 처음 보는 사람 1명이 안내만 보고 Surge XT에서 소리를 낸다(시간 기록, 목표 10분).

### S8-T2 국제화

- 범위: Fluent(ko.ftl, en.ftl), 시스템 언어 판별, 메뉴·설정·상태줄·오버레이·온보딩 전부, 템플릿 한국어 주석.
- 테스트 게이트: 두 로케일에서 미번역 키 0(검사 테스트). UI 스냅샷(텍스트만).

### S8-T3 성능·안정성 검증

- 범위: NF-1~9 전부를 재측정하고 `docs/reports/nf-results.md`에 표로. 야간 CI 1시간 재생(NF-3·NF-4). 메모리(NF-7) 측정 스크립트. 콜드 스타트(NF-6). 바이너리 크기(NF-9). 크래시 복구 시나리오(kill -9 중 저장).
- 테스트 게이트: 모든 수치가 REQ 8절 목표 안. 넘는 항목은 결정 요청(목표 수정 또는 추가 Task).

### S8-T4 접근성·테마

- 범위: UI-7·UI-8. 고대비, 폰트 크기, 색각 대응(판정은 모양으로도), 사용자 테마 JSON.
- 테스트 게이트: 색만 다른 두 상태가 없음을 검사하는 테스트(판정·조성 표시).

### S8-T5 서명 빌드와 배포

- 범위: 개인 Developer ID 서명(공증은 하지 않음 — 배포 전 재검토 항목으로 `docs/decisions/`에 남김), 유니버설 바이너리 시도, GitHub Releases 자동 업로드, Homebrew cask 정의, 도움말 「새 버전 확인」 링크, 텔레메트리 없음 확인(네트워크 호출이 AI 엔드포인트뿐임을 테스트로).
- 테스트 게이트: CI에서 서명 빌드 산출물 생성. 네트워크 호출 허용 목록 테스트.

### S8-T6 문서

- 범위: 각 crate README, 사용자 문서(키맵 표는 키맵 JSON에서 자동 생성), 계이름 텍스트 문법 문서(5.14를 사용자용으로), 기여 가이드(이 plan 폴더 참조).
- 테스트 게이트: 키맵 문서가 JSON과 일치(생성 테스트).

### S8-T7 식별자 일괄 변경 준비

- 범위: 제품명이 가칭이므로 `KeyScore`·`.ksq`·`KeyScore Out`이 한 곳(상수 모듈·빌드 설정)에서만 정의되게 정리. 바꾸면 전부 따라가는지 테스트.
