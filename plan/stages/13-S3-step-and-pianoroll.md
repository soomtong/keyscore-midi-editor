# S3 — 피아노롤과 Step 입력

목표: 피아노롤 뷰에서 키보드로 노트를 찍고, 고치고, 들을 수 있다. 이 단계가 끝나면 M1(첫 사용 가능 버전)이다.

관련 REQ: 4 P3, 5.1, 5.3, 5.6, 5.7, 5.8, 5.11(Step·Normal 부분), 7.4, 7.5, PRE-1, UI-3
선행: S2, SP-2

## Task 목록

### S3-T1 피아노롤 Element

- 범위: 자체 `Element`. 세로 음높이·가로 틱, 클립 하나의 안쪽, 앞뒤 클립 흐리게, 커서, 선택 강조, 재생 헤드(모노토닉 클록 보간, UI-4), 조성 안·밖 행 명암(조성 표시), 가로·세로 줌·스크롤, 인스펙터·레인과 가로 스크롤 동기(훅만).
- 결정 분기: SP-2에 따라 GPUI 프리미티브(A) 또는 자체 Metal 패스(B). → A(`docs/spikes/sp2-element-instancing.md`).
- 테스트 게이트: criterion — 10,000 노트 화면의 paint 시간 기준값 커밋, 60 fps 상한(16.7 ms) 안. UI 테스트 — 커서 이동 키가 뷰포트를 따라 스크롤.
  - 읽기(S3-T1 리뷰 1 지적 3): criterion 기준값은 순수 장면 계산 `pianoroll/scene_10k_notes`이고, GPUI 프레임(레이아웃·prepaint·paint)은 헤드리스 release 시험 `frame_with_10k_notes_fits_60fps_budget_in_release`가 16.7 ms 안을 단언한다. GPU 시간은 SP-2 측정에 기댄다. 실제 창의 10,000 노트 스크롤은 S3 출구 수동 항목이다.
- 리뷰 초점: paint 경로에서 매 프레임 할당·정렬이 있는가(노트는 틱 순 정렬 캐시를 써야 함).
- 이월(S3-T1 리뷰 1 제안 4, S3-T6에서): 주 뷰 네 변의 4 px 띠는 분할 손잡이 히트박스가 가려 클릭이 피아노롤에 닿지 않는다(맨 위 행의 4 px, 왼쪽 끝 40틱). 마우스 편집을 붙일 때 손잡이 폭이나 피아노롤 여백을 정한다.

### S3-T2 커서·선택·수식키 체계

- 범위: REQ 5.7 표 전체(없음/Shift/Ctrl/Ctrl+Shift/Alt/Alt+Shift/Alt+Ctrl × hjkl·화살표), `n`/`p`/`Shift+n`/`Shift+p`, `Cmd+화살표`, `[` `]`, `b`/`Shift+b`/`Cmd+A`, `Esc` 선택 해제, 이동 시 미리듣기(PRE-1), 되돌리기 묶음(연속 같은 조작).
- 테스트 게이트: 5.7 표의 모든 칸을 테이블 UI 테스트로(키 → 모델 변화). 선택 없을 때 `Alt` 조작이 커서 노트 하나에 적용.
- 리뷰 초점: `Alt+Shift+l` 연타가 하나의 undo로 묶이고, 다른 키가 끼면 묶음이 끊기는가.

- 이월(S2-T3, 결정 `docs/decisions/2026-10-17-keymap-conflicts.md` A13): vim `Normal > Operator`의 `escape` → `operator::Cancel`(신규, 오퍼레이터 대기·카운트 비움). 멀티키 시퀀스 대기 중(`g` 뒤)의 `Esc`는 시퀀스만 취소하고 다른 바인딩(선택 해제 등)을 실행하지 않는지 확인한다(GPUI 기본은 대기를 풀고 Esc를 디스패치한다).

- 이월(결정 `docs/decisions/2026-10-17-keymap-conflicts.md`, 2026-10-24 모두 권고안): S3-T2는 A2(`g a` 뷰 전환), A8(vim 피아노롤 `enter`=`note::Audition`, 배치 뷰 `enter`=`clip::Open` 상속), A10(`g b` 마디 선택, `g shift-b` 클립 선택), A11(`;` `,` 탐색 반복), A12(팔레트 `:` 접두 ex 명령 파서, `:w` `:q` `:e` `:new` `:set`)의 키를 `vim.json`에 채우고 `// 결정 대기` 주석을 지운다. S3-T3는 A1(`J`=`edit::Join`, `K`=`note::ShowInfo`), A9(vim 길이 `g 1`…`g 7`, `g 0`), B25(기호·숫자 모두 입력되는 글자 그대로, `shift-N` 바인딩 삭제)를 채운다. S3-T4는 B25의 Step 길이 코드 표기(`!` `@` … 점음표)를 같은 규칙으로 맞춘다. REQ 5.8·5.8.1·KM-7 문구는 같은 Task에서 고친다(결정 문서 「후속」).

- 이월(S2-T4, 결정 `docs/decisions/2026-10-17-vim-marks-visible-ui.md` a): 피아노롤·배치 뷰의 우클릭 메뉴에 「마크 설정 ▸ a–z」「마크로 이동 ▸ a–z」(`cursor::SetMark`, `cursor::JumpMark`)를 둔다(UI-11).

- 이월(S3-T1 리뷰 1 제안 3): `Ctrl+h`(한 마디 뒤로)를 S3-T1은 「마디 중간이면 그 마디 시작, 마디 시작이면 앞 마디 시작」으로 읽었다(`PianoRollState::move_cursor`). 5.7의 「한 마디 뒤까지」 선택(`Ctrl+Shift+h`)도 같은 읽기로 맞추고 계획에 한 줄로 고정한다. 「틱 − 마디 길이」로 읽으려면 결정 요청. → S3-T2가 같은 읽기로 고정했다(`docs/reports/s3-t2/plan.md` 1).

- 이월(S2-T5a 리뷰 1 제안 4): 재생은 곡 끝에서 스스로 멈추지 않는다(상태가 계속 재생 중). 커서·루프 구간과 함께 곡 끝 동작(멈춤 또는 계속)을 정한다. 일시정지 자리는 앱이 계산한 근삿값이라 루프 구간이 생기면 스케줄러에 위치 조회를 더할지도 이때 정한다. → S3-T2가 결정 요청 `docs/decisions/2026-10-25-playback-end-of-song.md`를 썼다. 결정이 나면 S3-T3 또는 S5 트랜스포트 Task가 구현한다.

- S3-T2가 끝낸 것(2026-10-25): 5.7 표 전체, `n`/`p`/`Shift+n`/`Shift+p`/`Cmd+←→`, `b`/`Shift+b`/`Cmd+A`/`Esc`, 미리듣기(PRE-1, 설정 `preview`), 되돌리기 묶음, A2·A8·A10(`g b`·`g shift-b`)·A11·A12(`:` 명령줄 `:w` `:q` `:e` `:new` `:set`), `operator::Cancel`, 시퀀스 대기 중 `Esc`, 피아노롤 우클릭 마크 메뉴, `Shift+Space`는 피아노롤 커서부터. 배치 뷰 쪽(우클릭 마크 메뉴, `Cmd+A` 클립 전체, 배치 뷰 커서부터 재생)은 S4-T1 이월.

### S3-T3 편집 동작

- 범위: REQ 5.8 선택·편집 표. `x`/`Delete`/`Backspace`, `Cmd+X/C/V/D`(앱 내부 클립보드 + 시스템 클립보드 SMF·텍스트, KM-15), `r` 반복, `/` 분할, `Cmd+J` 합치기, 숫자 길이 코드·`Shift+숫자`·`0`, `+`/`-`/`>`/`<`, `e` 음높이 바꾸기, `q`/`Shift+q`, `~` 레가토, `.` 반복. 붙여넣기가 클립 끝을 넘으면 클립 연장.
- 테스트 게이트: 각 동작의 단위 UI 테스트. 시스템 클립보드에 SMF 바이트와 텍스트가 둘 다 올라감. 다른 창에서 붙여넣기 가능.

### S3-T4 Step 모드와 길이 코드 문법

- 범위: REQ 5.1·5.6·5.11(Step). 건반형·계이름형 레이아웃, 기본 4분음표, 길이 코드 `1`–`7`·`0`, `Shift+코드` 점음표, `Shift+음` 절반 한 번, 뒤 숫자 옥타브(300 ms 확정·`Enter`·`Tab`), 변화표(계이름형), `n` 셋잇단, `Space` 쉼표, `Backspace`, `Ctrl+음` 화음, `~` 타이, `[` `]`·`Z`/`X` 옥타브, 상태줄 `STEP ♩ oct4`·조합 중 표시, 클립 밖에서 시작하면 마디 단위 클립 자동 생성·끝 넘으면 연장, undo는 노트 하나.
- 테스트 게이트: REQ 5.6 입력 예 표의 모든 행을 UI 테스트로(계이름형·건반형 둘 다). 300 ms 타임아웃을 가짜 클록으로 검증. `Shift+음`이 스티키가 아님.
- 리뷰 초점: 건반형에서 `n`·`Z`·`X`·숫자 줄이 음 키와 충돌하지 않는지 키맵 충돌 테스트로 확인.

- 이월(S2-T3, 결정 `docs/decisions/2026-10-17-keymap-conflicts.md` A13): 모드를 나가면(`Esc`, `Ctrl+Tab`) 조합 중 입력(`5c_`)은 현재 옥타브로 확정한다(REQ 5.6).
- 이월(S2-T3, 결정 `docs/decisions/2026-10-17-mode-entry-view.md`): 배치 뷰에서 Step에 들어가면 뷰는 배치 뷰 그대로다. 그 위치의 커서·클립 생성 표시를 그린다.

### S3-T5 건반 뷰

- 범위: 하단 건반 뷰(2옥타브, 키 라벨, 조성 강조, 옥타브 버튼), Step·Play 모드에서 표시, 드럼 트랙에서는 라벨 표시(5.13; Play 모드는 S5).
- 테스트 게이트: 현재 옥타브·레이아웃에 따라 라벨이 맞음(스냅샷).

### S3-T6 마우스 편집

- 범위: REQ 7.4 전체(선택 표·이동/조절 표·MS-1~7). 러버밴드, 고스트 미리보기, 스냅과 `Cmd` 해제, 끝 드래그 영역, 드래그 중 미리듣기, 키보드 커서 동기.
- 테스트 게이트: 마우스 이벤트 시뮬레이션 UI 테스트 — 다중 선택 드래그가 상대 위치 유지, 드래그 한 번이 undo 하나, `Esc`로 취소.
- 리뷰 초점: 마우스 조작이 키 조작과 같은 Action을 부르는가(중복 구현이면 차단).

- 이월(S2-T5b): 트랜스포트 템포·박자표 필드의 끌어서 조정(7.6 「클릭해 입력, 끌어서 조정」). S2-T5b는 입력 확정만 한다.
