# S3 — 피아노롤과 Step 입력

목표: 피아노롤 뷰에서 키보드로 노트를 찍고, 고치고, 들을 수 있다. 이 단계가 끝나면 M1(첫 사용 가능 버전)이다.

관련 REQ: 4 P3, 5.1, 5.3, 5.6, 5.7, 5.8, 5.11(Step·Normal 부분), 7.4, 7.5, PRE-1, UI-3
선행: S2, SP-2

## Task 목록

### S3-T1 피아노롤 Element

- 범위: 자체 `Element`. 세로 음높이·가로 틱, 클립 하나의 안쪽, 앞뒤 클립 흐리게, 커서, 선택 강조, 재생 헤드(모노토닉 클록 보간, UI-4), 조성 안·밖 행 명암(조성 표시), 가로·세로 줌·스크롤, 인스펙터·레인과 가로 스크롤 동기(훅만).
- 결정 분기: SP-2에 따라 GPUI 프리미티브(A) 또는 자체 Metal 패스(B). → A(`docs/spikes/sp2-element-instancing.md`).
- 테스트 게이트: criterion — 10,000 노트 화면의 paint 시간 기준값 커밋, 60 fps 상한(16.7 ms) 안. UI 테스트 — 커서 이동 키가 뷰포트를 따라 스크롤.
  - 읽기(S3-T1 리뷰 1 지적 3): criterion 기준값은 순수 장면 계산 `pianoroll/scene_10k_notes`이고, GPUI 프레임(레이아웃·prepaint·paint)은 헤드리스 release 시험 `frame_with_10k_notes_fits_60fps_budget_in_release`가 16.7 ms 안을 단언한다. GPU 시간은 SP-2 측정에 기댄다. 실제 창의 10,000 노트 스크롤은 S3 출구 수동 항목이다.
- 리뷰 초점: paint 경로에서 매 프레임 할당·정렬이 있는가(노트는 틱 순 정렬 캐시를 써야 함).
- 이월(S3-T1 리뷰 1 제안 4, S3-T6에서): 주 뷰 네 변의 4 px 띠는 분할 손잡이 히트박스가 가려 클릭이 피아노롤에 닿지 않는다(맨 위 행의 4 px, 왼쪽 끝 40틱). 마우스 편집을 붙일 때 손잡이 폭이나 피아노롤 여백을 정한다.

### S3-T4 Step 모드와 길이 코드 문법

- 범위: REQ 5.1·5.6·5.11(Step). 건반형·계이름형 레이아웃, 기본 4분음표, 길이 코드 `1`–`7`·`0`, `Shift+코드` 점음표, `Shift+음` 절반 한 번, 뒤 숫자 옥타브(300 ms 확정·`Enter`·`Tab`), 변화표(계이름형), `n` 셋잇단, `Space` 쉼표, `Backspace`, `Ctrl+음` 화음, `~` 타이, `[` `]`·`Z`/`X` 옥타브, 상태줄 `STEP ♩ oct4`·조합 중 표시, 클립 밖에서 시작하면 마디 단위 클립 자동 생성·끝 넘으면 연장, undo는 노트 하나.
- 테스트 게이트: REQ 5.6 입력 예 표의 모든 행을 UI 테스트로(계이름형·건반형 둘 다). 300 ms 타임아웃을 가짜 클록으로 검증. `Shift+음`이 스티키가 아님.
- 리뷰 초점: 건반형에서 `n`·`Z`·`X`·숫자 줄이 음 키와 충돌하지 않는지 키맵 충돌 테스트로 확인.
