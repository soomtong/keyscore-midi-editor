# S4 — 클립과 배치 뷰

목표: 곡을 트랙 위의 클립으로 구성하고, 클립을 옮기고 자르고 복제한다.

관련 REQ: 5.10, 5.11(배치 뷰·트랙 이동), 7.4(클립 부분), SEQ-2, 트랙 관리(7.6)
선행: S3

## Task 목록

### S4-T1 배치 뷰 Element

- 범위: 트랙×시간 격자, 클립 블록(이름·색·첫 소절 가사 흐리게), 커서(트랙, 틱), 선택, 재생 헤드, 줌·스크롤, `v` 전환·`Enter` 진입·`Esc` 복귀.
- 테스트 게이트: 벤치(트랙 64 × 클립 200). UI 테스트 — `v`/`Enter`/`Esc` 전이.
- 이월(S3-T1 리뷰 1 제안 7): `view::ZoomIn/ZoomOut/ZoomReset/CenterCursor` 처리기는 뷰와 무관하게 창에 걸려 있어 배치 뷰에서도 숨은 피아노롤을 줌한다. 배치 뷰가 자기 줌을 가지면 현재 뷰에 따라 나눈다(`pianoroll_window.rs`의 `piano_roll_handlers`).
- 이월(S3-T2): 배치 뷰 Element에 피아노롤과 같은 우클릭 메뉴 「마크 설정 ▸ a–z」「마크로 이동 ▸ a–z」를 단다(`ProjectWindow::open_piano_roll_menu`와 같은 `open_popup_with`, 결정 `2026-10-17-vim-marks-visible-ui` a). `select::All`은 배치 뷰에서 클립 전부를 선택한다(지금은 아무 일도 하지 않음, `selection.rs` `select_all`). `transport::PlayFromCursor`는 배치 뷰 커서가 생기면 그 커서부터(지금은 처음부터, `transport_play_from_cursor`). `cursor::NextClip/PrevClip/ClipStart/ClipEnd`·마크는 지금 피아노롤 커서(창에 하나)를 움직인다. 배치 뷰 커서를 따로 두면 뷰에 따라 나눈다.

### S4-T2 클립 조작 키

- 범위: REQ 5.10 표와 목록. 수식키 체계의 클립 단위 적용, `Shift+이동` 선택, `x`/`Cmd+X/C/V/D`(겹치면 뒤로 밀기), `r`, `/` 분할(레인 데이터 경계 보간, CTL-7 준비), `Cmd+J`, 비파괴 트림(줄여도 노트 보존, 늘리면 복귀), 빈 공간 확장, 트랙 간 이동 시 채널 경고.
- 테스트 게이트: proptest — 임의 클립 조작 수열 뒤 겹침 없음·노트 보존(트림 후 복원 시 원본과 동일). 각 키의 테이블 UI 테스트.
- 리뷰 초점: 트림된 노트가 어디에 어떻게 보관되는가, 저장·불러오기 후에도 복원되는가.
- 이월(S0-T2): 결정 Q1에 따라 「분할 → 합치기 = 원본」(숨김 꼬리 복원) 속성 테스트를 넣는다.

### S4-T3 트랙 관리와 `Tab` 트랙 이동

- 범위: `Cmd+T` 새 트랙(채널 자동 배정, 팔레트 순서 색), 삭제·순서 바꾸기, `m`/`o`, `Tab`/`Shift+Tab` 트랙 이동(시간 유지, 음높이는 트랙의 마지막 편집 음 또는 C4, 클립 없으면 배치 뷰 빈 자리), `(`/`)` 별칭.
- 테스트 게이트: 새 트랙 10개의 채널이 1–9, 11–… (10 건너뜀)로 배정. `Tab` 이동 후 커서 시간 불변.
- 이월(S0-T2 리뷰): 트랙 복제는 `ClipId`를 새로 발급해야 한다. `Track::clone`은 id를 그대로 복사하므로(undo 스냅샷용) 복제 기능에 쓰지 않는다.

### S4-T4 클립 뷰에서의 마우스

- 범위: REQ 7.4 클립 열(러버밴드, 드래그, 끝 트림, `Alt` 복제, 더블클릭 생성·진입).
- 테스트 게이트: S3-T6과 같은 기준.

### S4-T5 새 프로젝트 기본값·최근 파일·창 간 클립보드

- 범위: 새 프로젝트(Lead ch1, Drums ch10, 120, 4/4, 조성 없음), 창 간 복사·붙여넣기.
