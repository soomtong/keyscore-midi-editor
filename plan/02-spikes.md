# 02 — 스파이크 (착수 전 기술 검증)

REQ 12.1의 미결 질문을 사실로 바꾼다. 각 스파이크는 제품 코드에 남지 않는 독립 실험이며, 결과를 `docs/spikes/<이름>.md`에 「질문 / 방법 / 결과 / 계획에 미치는 영향」 네 항목으로 적는다. 하루를 넘기지 않는다. 넘기면 「확인 못 함」으로 기록하고 보수적인 분기를 택한다.

## SP-1 GPUI 키 이벤트 타임스탬프

- 질문: gpui-kit이 고정한 GPUI 스냅샷에서 `NSEvent.timestamp`가 키 이벤트·Action 핸들러까지 전달되는가?
- 방법: 최소 GPUI 창에서 키 핸들러 안의 타임스탬프와 `mach_absolute_time()`을 비교. 없으면 `NSEvent.addLocalMonitorForEvents`로 받은 타임스탬프를 GPUI 핸들러와 짝지을 수 있는지 확인.
- 영향: 있으면 S5-T2(레이턴시 보정)가 단순해진다. 없으면 S5-T2의 분기 B(로컬 이벤트 모니터)를 쓴다.

## SP-2 GPUI 커스텀 Element 인스턴싱

- 질문: 자체 `Element`로 사각형 10,000개(노트)를 60 fps로 그릴 수 있는가? `paint`에서 쓸 수 있는 프리미티브가 무엇인가?
- 방법: 10,000개 사각형을 스크롤·줌하는 Element를 만들고 Instruments로 프레임 시간 측정.
- 영향: 가능하면 S3-T1은 GPUI 프리미티브만 쓴다. 불가능하면 분기 B(자체 Metal 패스 삽입)로 가고 S3 기간이 늘어난다.

## SP-3 coremidi 크레이트 범위

- 질문: `coremidi` 크레이트로 가상 소스 생성, 포트 열거·핫플러그 콜백, 타임스탬프 지정 송신이 되는가? MIDI 1.0 프로토콜 소스로 만들 때 수신 앱(Surge XT 등)이 바로 보는가?
- 방법: 가상 소스를 만들고 Surge XT에서 입력으로 선택, 미래 타임스탬프로 Note On을 보내 도착 시각을 수신 테스트 앱에서 측정.
- 영향: 부족한 API는 `core-midi-sys`로 직접 호출(S1-T1 분기 B).

## SP-4 가상 포트 리스너 감지

- 질문: 가상 소스에 다른 앱이 연결했는지 CoreMIDI로 알 수 있는가?
- 방법: `MIDIObjectGetIntegerProperty`의 연결 관련 속성, `MIDINotification` 종류를 조사.
- 영향: 있으면 PRE-2의 상태줄 표시를 구현. 없으면 「테스트 노트 보내기」 안내만(S8-T1).

## SP-5 소형 LLM의 계이름 텍스트 안정성

- 질문: `openai/gpt-5.6-luna`, `~anthropic/claude-haiku-latest`, 로컬 모델 1종이 REQ 5.14 문법으로 8마디 멀티트랙을 얼마나 안정적으로 내는가?
- 방법: 시스템 템플릿 초안 + 픽스처 4개 × 모델 3개 × 5회 = 60회. 파싱 성공률, 마디 수 일치율, 응답 시간을 표로.
- 영향: 파싱 성공률 90% 미만인 모델은 기본값에서 제외. 문법 자체가 문제면 S0-T5의 문법을 손본다(결정 요청).

## SP-6 어시스트 지연

- 질문: 어시스트 요청(컨텍스트 ~600토큰, 응답 ≤300토큰)의 p50·p95 응답 시간은? 2 s 상한이 현실적인가?
- 방법: SP-5와 같은 템플릿으로 30회 측정.
- 영향: p95가 2 s를 넘으면 상한을 올리거나 컨텍스트를 줄인다(S7-T4 분기).
