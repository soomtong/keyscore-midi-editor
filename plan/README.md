# KeyScore 구현 작업 계획 — 코딩 에이전트용

이 폴더는 요구사항 문서(「키보드 중심 MIDI 시퀀서 요구사항 문서」, 이하 REQ)를 코딩 에이전트가 순차적으로 구현할 수 있도록 쪼갠 작업 계획이다. 에이전트는 파일을 번호 순서대로 읽고, 각 단계 안에서는 작업(Task)을 번호 순서대로 처리한다.

## 진행 규칙 요약

1. `00-conventions.md`와 `01-protocol.md`를 먼저 읽는다. 이후 모든 작업에서 이 두 파일을 전제한다.
2. `02-spikes.md`의 스파이크를 S0 전에 끝낸다. 스파이크 결과는 `docs/spikes/<이름>.md`에 남기고, 결과가 계획의 가정과 다르면 해당 단계 파일의 「결정 분기」 항목을 따른다.
3. 단계(Stage)는 순서대로 진행한다. 단계의 「출구 게이트」를 통과하기 전에는 다음 단계를 시작하지 않는다.
4. Task 하나는 하나의 브랜치·하나의 PR이다. Task마다 「계획 → 구현 → 검증 → 적대적 리뷰 → 수정 → 병합」 루프를 돈다(`01-protocol.md`).
5. Task 안에서 요구사항 문서와 어긋나는 점을 발견하면 임의로 결정하지 않는다. `docs/decisions/`에 결정 요청 파일을 만들고 사람의 답을 기다린다. 답이 없으면 그 Task를 보류하고 의존하지 않는 다음 Task로 간다.
6. 모든 산출물(코드, 테스트, 문서, 보고서)은 저장소에 커밋한다. 대화 안에만 남는 것은 없다.

## REQ 참조 규칙

각 Task는 REQ의 절 번호와 요구사항 ID(SEQ-7, KM-3, AI-11 등)를 명시한다. 구현 중에 REQ를 다시 읽어야 할 때는 그 절만 읽는다. REQ 전체를 매번 읽지 않는다.

## 용어

- Task: 하나의 PR로 끝나는 작업 단위. 보통 반나절에서 이틀 분량.
- 게이트: 통과해야 다음으로 갈 수 있는 자동·수동 검사. 자동 게이트는 CI가, 수동 게이트는 사람이 통과를 확인한다.
- 적대적 리뷰: 구현자와 다른 세션(또는 다른 역할 프롬프트)의 에이전트가 「이 코드를 깨뜨리는 것」을 목표로 수행하는 리뷰.
- 스파이크: 결정을 위해 사실을 확인하는 짧은 실험. 제품 코드에 남기지 않는다.
