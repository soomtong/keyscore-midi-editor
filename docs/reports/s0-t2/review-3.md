## 1. 코드만 읽고 적은 「내가 검사할 것」

`git diff 954d814..HEAD`의 제품 코드(`track.rs`, `note.rs`)만 읽고 적었다.

1. `move_clip`이 `self.clips[index].1.set_start(..)?`로 제자리에서 바꾼 뒤 `remove` + `place`로 재정렬한다. 사전 검사(`end`, `extent`)가 어긋나 `set_start`가 실패하는 경우 클립은 원래 자리에 있다. 단, 사전 검사를 통과한 뒤 `set_start`가 실패할 수 있는 경로가 하나라도 있는가.
2. 재정렬이 맞는가: 맨 앞으로, 맨 뒤로, 자기 자리로, 자기 자리에서 한 틱 이동, 이웃 클립에 맞닿는 경계. `place`는 `partition_point(start < new_start)`라 같은 시작 틱 클립이 없으면(겹침 금지) 문제없어야 한다. `remove(index)` 뒤 인덱스가 밀려 `place`가 옛 자리를 기준으로 계산하지 않는가.
3. 이동 후 노트 수·식별자·이름·색이 유지되는가(제자리 변경이라 유지되어야 한다).
4. 실패 시 `track == before`(파생 `PartialEq`, 식별자 포함)인가. 오버플로 실패를 클립 인덱스 0·중간·끝에서 모두 본다.
5. `to_midi1` 주석 변경은 동작을 바꾸지 않는가(문서만).
6. `model_invariants.rs`의 `tick()` 전략과 `SplitClip { offset }` 변경이 실제로 꼬리 오버플로 퇴화를 잡는가. 구현자는 「extent 검사를 빼면 세 번 실행 모두 실패」라고 했다. `.proptest-regressions`에 기록된 시드가 없어도 잡는가(시드 파일은 재생될 뿐이라 결정적이다).
7. `.proptest-regressions`에 한 줄을 더한 것이 정당한가(실패 시드의 기록). 파일 형식이 깨지지 않았는가.
8. 지적 1(문서 불일치)이 README·계획·보고서에서 결정 Q2·Q3과 맞는가.
9. 제안 4·5를 「기록만 함」으로 둔 대응이 추적 가능한가. 기록이 다음 Task(S0-T4·S0-T6·S4)가 읽는 파일에 있는가.
10. 결정 요청 `absolute-pitch-range.md`가 선택지·추천·병합 비차단 근거를 갖췄고 REQ ID를 맞게 인용하는가.
