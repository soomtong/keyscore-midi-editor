# 적대적 리뷰: S1-T1 CoreMIDI 가상 출력 포트 (리뷰 6회차)

- 리뷰어 세션: 구현 맥락을 물려받지 않은 별도 서브 에이전트 세션(구현자·리뷰 1–5 리뷰어와 다른 세션)
- 대상 커밋: `2a37925` `midi: Build the duplicate key after removing invisible characters` (브랜치 `s1/t1-virtual-port`, HEAD `43a300a`). 코드 변경은 `crates/keyscore-midi/src/client.rs`의 `duplicate_key` 하나와 결정 문서 한 줄뿐이다(`git diff 80e254c HEAD -- crates/ docs/decisions/`).
- 범위: 중복 키 생성 순서 수정만. 재시도 잠금(리뷰 5 제안 2)과 1–5회차에서 확인된 성질은 다시 훑지 않았다.
- 남긴 테스트: `crates/keyscore-midi/tests/review_s1_t1_r6.rs` (실패 2, 통과 2)

## 1. 코드만 읽고 적은 「내가 검사할 것」

`duplicate_key` diff와 결정 문서, review-5, report.md의 review-5 대응 표만 보고 적었다.

1. 리뷰 1–5 테스트 파일이 그대로인가. 리뷰 5 실패 2건이 HEAD에서 통과하고, `client.rs`만 `80e254c`로 되돌린 사본에서 다시 실패하는가.
2. 과잉 병합(키가 같은데 모양이 다름). 표시되지 않는 문자를 뺀 뒤 NFC를 다시 하므로, 빼낸 문자가 갈라 놓았던 글자가 키에서 새로 합쳐질 수 있다. ZWJ·ZWNJ 뒤의 결합 문자(악센트가 떨어져 그려진다고 리뷰 5가 적었다), 한글 조합형 낱자 사이의 결합자·이체자 선택자.
3. 과잉 병합 2. 빈칸 모양 문자를 키에서 「뺀다」. 그런데 이 문자들은 폭이 있다(U+2800 등). 글자 사이에 있으면 틈이 보이는데 키에서는 틈이 사라진다.
4. 남은 빈틈(모양이 같은데 키가 다름). 허용 예외 문자·폭 없는 빈칸 모양 문자를 아무 위치에 끼운 이름, 공백 종류·개수·앞뒤 공백 변형과 그 조합, NFD 이름, 끝에 붙인 점자 빈칸.
5. 키 함수의 대칭. `create_virtual_output`, `rename`, `drop`이 같은 `duplicate_key`를 쓰고, 새 규칙으로만 같아지는 이름으로 rename한 뒤 해제가 정확히 그 키를 푸는가.
6. 결정 문서 변경. 사람이 쓴 「결정」 줄에 에이전트가 무엇을 더했는가. 리뷰 5가 「결정 범위 밖」이라 한 빈칸 모양 문자 정책이 사람 결정처럼 적혔는가.
7. 15회 이상 반복 실행에서 간헐 실패가 나오는가.

## 6. 실시간·에러 경로

- 스케줄러 경로의 할당·락·로그: `send`는 바뀌지 않았다. `duplicate_key`의 할당은 생성·rename·drop에서 `PORT_NAMES` 잠금 안에서만 일어난다(이전과 같다).
- 제품 코드의 `unwrap`/`expect`: 없음.
- 에러가 삼켜지는 곳: `VirtualOutput::drop`의 dispose 결과(이전과 같다).
- 새 의존성: 없음(`unicode-normalization`은 이미 쓰던 것).
