# 적대적 리뷰: S3-T4c 미리듣기 가벼운 경로와 배치 뷰 Step 표시 (리뷰 2회차)

- 리뷰어 세션: 구현 세션과 다른 새 서브 에이전트(구현 컨텍스트를 물려받지 않음). 리뷰 1 세션과도 다르다
- 대상 커밋: `aee02a5` (범위 `e91d0e8..HEAD`: `ccae155`, `59ef75c`, `59a057e`, `aee02a5`)

## 1. 코드만 읽고 적은 「내가 검사할 것」

1. `step_write` 리팩터링: 트랙 없음 알림(「Step: 트랙이 없다」), `Note::new`·`starting_in`·`splice`의 차례, 덮어쓰기의 `remove`·`by`, 새 클립 id 찾기, 실패 알림 「Step: 쓰지 못했다: …」가 그대로인가.
2. `next_step_write`가 `step_commit`의 앞 단계를 모두 따라 하는가: `step_settle_mml`(MML 대기 확정, 길이가 바뀜), 다른 트랙 화음 닫기(커서가 화음 끝으로 감), 같은 트랙 열린 화음의 다음 음(`push` = 0).
3. 조합이 없는데 화음이 열린 상태: 표시는 `push` = 길이로 계획하는데 실제 다음 음은 0으로 민다.
4. 조합 음높이가 0–127 밖(변화표·`OctaveOnce`)일 때 표시와 확정 알림이 같은가.
5. 표시가 쓰는 트랙(`current_track`)과 확정이 쓰는 트랙(`Composing::track`)이 다를 수 있는가(트랙 이동은 Step을 확정하지 않는다).
6. 덮어쓰기에서 표시가 화음 첫 음을 지울 노트로 세는 경우의 문구 차이.

## 6. 실시간·에러 경로

- 스케줄러 경로의 할당·락·로그: 없음(이 범위는 메인 스레드의 표시·쓰기 계획만 바꿈).
- 제품 코드의 `unwrap`/`expect`: 새로 생긴 것 없음. `u64::try_from(push).unwrap_or(0)`은 옮겨 온 것.
- 에러가 삼켜지는 곳: 없음. 계획 오류는 표시(「여기서는 쓸 수 없다(…)」)와 쓰기 알림 양쪽으로 나온다.
