## 1. 코드만 읽고 적은 「내가 검사할 것」

리뷰 1 대응 diff(`git diff 61283fd..HEAD -- crates/keyscore-app/src`)만 읽고 적었다.

1. space 처리기가 선택 상자가 열린 뒤 검색란의 공백을 가로채지 않는가(「Side Stick」처럼 공백이 든 검색어).
2. space로 열고 고른 뒤 포커스가 선택 상자로 돌아와 다시 space로 열리는가. escape로 닫은 뒤도 같은가.
3. space가 설정 창 밖(프로젝트 창 재생)으로 새지 않는가.
4. 재생 중 교체가 늘 `set_metronome_enabled(false)`를 먼저 넣으므로, 버튼이 꺼진 상태에서 끝의 켜기 값이 버튼을 무시하고 켜 버리지 않는가.
5. 메트로놈 포트가 없는(missing) 상태에서 버튼을 껐다 켜거나 다른 값을 바꿔 교체가 일어날 때 옛 포트 번호로 클릭이 새지 않는가(`clicks()`와 교체 경로의 켜기 값이 일치하는가).
6. 교체를 빠르게 여러 번 거듭할 때 끝 상태가 마지막 선택과 맞는가.
7. 재생 시작 경로(`play_from`)와 재생 중 교체 경로의 명령 순서가 서로 어긋나 생기는 틈.
8. 교체 경로의 오류 처리: 끄기는 들어갔는데 교체가 실패하면, 또는 `set_metronome`이 실패해 켜기를 건너뛰면 버튼·표시·스케줄러 상태가 어긋나는가.

## 6. 실시간·에러 경로

- 스케줄러 경로의 할당·락·로그: 이번 대응은 스케줄러(`keyscore-midi`)를 고치지 않았다. 제어 스레드에서 명령 하나(`MetronomeEnabled(false)`)를 더 넣을 뿐이다. 없음.
- 제품 코드의 `unwrap`/`expect`: 새로 더한 것 없음.
- `play_from`과의 비교: 재생 시작은 `stop` → `swap` → `set_metronome` → `set_metronome_enabled` → `play` 순서다. 스케줄러가 재생 중이 아닐 때는 클릭을 예약하지 않으므로 끄기를 먼저 넣지 않아도 틈이 없다. 두 경로의 차이는 정당하다.
- 에러가 삼켜지는 곳: 없음. 다만 교체 경로의 오류 뒤 상태가 어긋날 수 있다(제안 1).
