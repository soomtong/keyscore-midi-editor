# 적대적 리뷰: S1-T6 SMF 입출력 (리뷰 3회차)

- 리뷰어 세션: 구현 세션·리뷰 1·리뷰 2 세션과 다른 새 서브 에이전트 세션. 구현 컨텍스트를 물려받지 않았다.
- 대상 커밋: 972a06a (브랜치 `s1/t6-smf`, 리뷰 2 이후 변경 `1ef7669..HEAD`)
- 범위: 마지막 확인 리뷰. (A) 리뷰 2 지적 1–3이 근본에서 해결되었는가, 그리고 `smf/song.rs`·`smf/raw.rs`에 `SmfLimits` 안에서 이차로 자랄 수 있는 정렬 삽입·중첩 탐색이 남았는가, (B) 화음 가사 자리가 모델 → SMF → 모델과 SMF → 곡 → SMF에서 지켜지는가, (C) 회귀 없음과 거절한 제안 4.
- 깨뜨리는 테스트: `crates/keyscore-midi/tests/review_s1_t6_r3.rs`

## 1. 코드만 읽고 적은 「내가 검사할 것」

`git diff 1ef7669..HEAD -- crates/`와 `song.rs`·`raw.rs` 전체만 보고, 테스트를 쓰기 전에 적었다.

1. 지적 1: `to_project`가 모델 노트를 `Note`의 `Ord`로 정렬한 뒤 넣는다. `Clip::insert_note`의 `partition_point(n <= &note)`와 같은 순서이므로 늘 끝에 붙는가.
2. 지적 2: `attach_lyrics`는 붙이기를 `extend` + 안정 정렬로 바꿨다. 그러나 함수 자체가 가사만 든 SMF 트랙마다 한 번 불리고, 매번 모든 곡 트랙의 모든 노트를 훑고 대상 가사 전체를 정렬한다. 가사 트랙 수(최대 1023) × 노트 수(최대 약 100만)가 되는가.
3. `split_track`의 `add_cc`·`add_program`·`add_bend`·`add_pressure`·`add_lyric`은 정렬 삽입이다. 한 SMF 트랙의 이벤트는 틱 순이라 늘 끝에 붙는가. 같은 곡 트랙에 두 SMF 트랙이 합쳐지는 경로가 있는가.
4. `from_project`의 `add_lyric`은 (틱, 음높이, 길이)로 정렬한 뒤 넣으므로 끝에 붙는가.
5. `to_project`의 `project.push_track`은 트랙 id를 선형으로 찾는다. 곡 트랙 최대 1024 × 16에서 의미 있는가.
6. 지적 3: 자리 키가 (틱, 음높이, 내보낸 길이)다. 같은 키의 노트가 둘 이상이면 내보내기는 클립 순서(시작, 음높이, 모델 길이, 오프셋, 벨로시티)로 가사를 내고, 가져오기는 `by_bar`의 곡 순서(시작, 길이, 음높이, 벨로시티)로 큐에서 꺼낸다. 숨김 꼬리로 모델 길이가 다른 두 노트가 같은 길이로 잘리면 두 순서가 어긋나는가.
7. 같은 음높이 노트가 겹치면 SMF의 FIFO 짝짓기로 길이가 바뀐다. 같은 틱 무리 안에서 길이 순서는 유지되는가.
8. SMF → 곡에서 가사가 사라지는 경로: 채널 메시지는 있지만 나눈 채널 트랙이 모두 비어 버려지는 SMF 트랙(짝 없는 Note Off, 폴리 프레셔만)의 가사.
9. `raw.rs`의 읽기·쓰기는 이벤트마다 상수 시간인가.

## 7. 지적 사항

| # | 심각도(차단/수정/제안) | 내용 | 파일:줄 |
| --- | --- | --- | --- |
| 1 | 수정 | 리뷰 2 지적 2(와 리뷰 1 지적 2)의 근본이 남았다. `attach_lyrics`는 호출 하나만 선형이고, 가사만 든 SMF 트랙마다 불려 매번 모든 곡 트랙의 노트를 훑고 대상 가사 전체를 정렬한다. 가사 트랙 1000개 × 노트 99만 개에서 41 s(가사 트랙 1개 0.40 s, 입력 크기 거의 같음). 노트 시작 틱 → 트랙별 개수를 한 번만 만들고 모든 가사 트랙을 그것으로 고른 뒤, 트랙마다 한 번만 정렬해야 한다. 테스트 `many_single_lyric_tracks_with_many_notes_import_in_bounded_time` | `song.rs:282-284`, `301-319` |
| 2 | 수정 | 리뷰 2 지적 3의 부분 수정. 자리 키 (틱, 음높이, 내보낸 길이)가 같은 노트가 둘 이상이면 내보내기는 클립 순서(모델 길이, 오프셋, 벨로시티)로, 가져오기는 곡 순서(벨로시티)로 가사를 짝짓는다. 숨김 꼬리가 같은 길이로 잘리면 모델 길이 순서와 벨로시티 순서가 어긋나 가사가 다른 노트로 간다(같은 음높이·길이에 오프셋만 다른 노트도 같은 원인). `from_project`에서 같은 키 안의 가사 순서를 곡 순서(내보낸 길이, 벨로시티)로 정하면 된다. 테스트 `hidden_tail_chord_lyrics_with_equal_cut_length_stay_on_their_notes` | `song.rs:446-458`, `815-819` |
| 3 | 수정 | 채널 메시지는 있지만 노트·CC·프로그램·벤드·프레셔가 없는 SMF 트랙(폴리 프레셔나 짝 없는 Note Off만)의 Lyric 메타가 SMF → 곡에서 오류 없이 사라진다. 나눈 채널 트랙이 모두 버려지면 그 가사를 `orphan_lyrics`로 넘기면 된다. 테스트 `lyric_track_with_stray_channel_message_keeps_lyrics` | `song.rs:274-280`, `625-639` |
