# 적대적 리뷰: S3-T3e 퀀타이즈 설정 시트 (리뷰 2회차)

- 리뷰어 세션: 구현자와 다른 세션(적대적 리뷰 전용 서브 에이전트, 구현 컨텍스트를 물려받지 않음)
- 대상 커밋: ee86cb0(1회차 뒤 수정, 시트 포커스 이탈 시 취소). 범위는 이 커밋으로 좁혔다. 1회차에서 본 영역의 새 모서리는 「제안」으로만 적는다.

## 1. 코드만 읽고 적은 「내가 검사할 것」

1. 시트 안 버튼(‹ › 확인 취소)·줄 클릭이 포커스를 시트 밖으로 옮겨, 클릭 처리기보다 먼저 포커스 이탈 취소가 시트를 닫지 않는가(특히 확인 버튼이 취소로 처리되지 않는가).
2. 오른쪽 클릭(버튼이 포커스를 가져가는 경우, 루트 `focus_document_on_press`)으로 시트가 닫히거나 포커스 없는 고아가 되지 않는가.
3. 팔레트·`?` 오버레이·모드 메뉴를 시트에서 열 때, 늦게 오는 포커스 이탈 콜백이 `close_quantize_sheet`를 다시 불러 문서로 포커스를 돌려 새 팝업을 깨지 않는가(이중 닫기).
4. 닫은 뒤 구독이 남아 다음 시트나 다른 동작(템포 필드 포커스 등)에 끼지 않는가. 특히 닫고 그릴 틈 없이 다시 열 때 앞 시트의 구독이 새 시트를 닫지 않는가.
5. 창 비활성(다른 창 활성화)으로 포커스 경로가 비어도 시트가 남고, 재활성 뒤 초안·포커스가 그대로인가. GPUI가 비활성 전환 때 `on_focus_out`을 부르는 순서와 `is_window_active()` 값이 맞는가.
6. 이미 열린 상태에서 `edit::QuantizeSettings`를 다시 받으면 구독을 새로 만들지 않고 초안을 지키는가.
7. 포커스 이탈 취소 뒤 포커스가 새 대상(템포 필드)에 남고, 메시지·undo가 없고, 초안이 새지 않는가.
8. 구독 활성화가 `defer`라서 열자마자 같은 흐름에서 포커스가 나가면 놓치는 틈이 있는가.

## 6. 실시간·에러 경로

- 스케줄러 경로의 할당·락·로그: 없음(UI 스레드 코드만).
- 제품 코드의 `unwrap`/`expect`: 이번 커밋에서 늘지 않았다. `let Some(sheet) = &self.quantize_sheet else { return; }`(`quantize_sheet.rs:177`)는 바로 위에서 채웠으므로 닿지 않는 갈래이고 `expect` 대신 조용히 돌아간다. 문제없다.
- 에러가 삼켜지는 곳: 없음.
- GPUI 동작 확인(`gpui-pre-0.3.8/src/window.rs` 3392–3430, `app/context.rs` 635–662): 창 비활성 전환 프레임에서 현재 포커스 경로를 비워 `on_focus_out`이 불리지만 그때 `is_window_active()`는 `false`라 닫지 않는다. 재활성 프레임은 이전 경로를 비우므로 콜백이 불리지 않는다. 구독 활성화는 `cx.defer`라 같은 효과 흐름 안의 포커스 이동은 놓칠 수 있으나, 여는 처리기가 마지막에 시트로 포커스를 주므로 그 흐름에서 시트 밖으로 나갈 사용자 경로를 찾지 못했다.
