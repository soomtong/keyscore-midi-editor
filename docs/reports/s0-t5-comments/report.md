# 변경 보고: 계이름 텍스트 주석을 `//`로 (결정 Q1 개정)

- 브랜치: `s0/t5-slash-comments`
- 근거: 사람 지시(2026-10-16) 「토큰 표: 주석은 `//`으로 통일하고 `#`을 주석으로 사용하지 않도록 한다(복잡함을 줄이자)」. `docs/decisions/2026-10-11-ktext-grammar-ambiguities.md` Q1 개정
- 관련 REQ: 5.1(입력 예), 5.14(예시 블록, 토큰 표)
- 성격: S0-T5(계이름 텍스트 파서·내보내기)의 동작 변경. Task 루프(테스트 먼저 → 구현 → 게이트 → 적대적 리뷰 → 병합)를 따른다.

## 바뀐 동작

| 입력 | 전 | 후 |
| --- | --- | --- |
| `// 메모`, `c4// 메모` | 모르는 토큰 `/` 둘 | 줄 끝까지 주석 |
| `# 메모`(트랙 블록 안의 줄 첫머리·공백 뒤) | 주석 | 모르는 토큰 `#`. 엄격 모드 오류, 느슨 모드 경고 후 `#` 한 글자 건너뜀(뒤의 글자는 토큰으로 읽힘). 메시지에 「주석은 //」 |
| `# 메모`(첫 `@track` 앞) | 주석 | 두 모드 모두 오류(헤더 영역의 다른 모르는 토큰과 같다). 메시지에 「주석은 //」 |
| `c4# d` | `c4`, 뒤는 주석 | `c4`, 모르는 토큰 `#`, `d` |
| `c#`, `c+#`, `@key F# minor` | 올림표 | 그대로 |
| `@track Lead#2 ch1` | 이름 `Lead`, 나머지는 주석 | 이름 `Lead#2` |
| `@track A//x ch1` | 이름 `A//x` | 이름 `A`, 나머지는 주석 |
| 가사·따옴표 이름 안의 `#`, `//` | 글자 | 글자 |
| 내보내기 트랙 이름 | `#`가 들면 따옴표 | `//`가 들면 따옴표, `#`는 그대로 |

## 리뷰어에게

1. 옛 `#` 주석을 쓴 파일의 처리. 결정의 결과로 받아들였다.
   - 첫 `@track` 앞(옛 파일의 첫 줄 주석 자리)의 `#`는 두 모드 모두 오류다. 가져오기가 실패하고, 오류에 「주석은 //」가 붙는다(리뷰 1 지적 1 뒤).
   - 트랙 블록 안의 `# 메모`는 느슨 모드에서 `#` 한 글자만 건너뛰고 경고한다. 뒤의 `메모`는 글자마다 모르는 토큰이나 음으로 읽힐 수 있다. 음이름 글자(`a`–`g`)가 있으면 음이 생긴다.
   - `#`로 시작하는 줄 전체를 건너뛰는 이행 규칙을 둘지는 사람이 정할 일이다. 아직 배포된 옛 파일은 없다.
2. `@time 4/4`의 `/`와 주석의 `//`가 섞이는 입력(`@time 4//4`).

| # | 지적 | 대응 |
| --- | --- | --- |
| 1 | 첫 `@track` 앞의 `#`가 느슨 모드에서도 실패. 결정 문구(「느슨 모드는 경고」)와 다름 | 리뷰의 방법 (b)를 택했다. 헤더 영역의 모르는 토큰은 이미 두 모드 모두 오류다. 트랙 밖의 음이 오류, 겹친 BOM이 실패인 기존 테스트가 있다. 그래서 `#`도 그 규칙을 따르고 오류에 「주석은 //」를 붙였다. 개정을 옮겨 적을 때 정확하지 않게 쓴 결정 문구와 보고서를 「트랙 블록 안만 느슨 모드 경고」로 바로잡았다. (a)(헤더 영역도 경고)는 기존 두 테스트와 부딪쳐 택하지 않았다 |
