## 1. 코드만 읽고 적은 「내가 검사할 것」

`git diff 8e9d920 HEAD -- tools/ksq-cli/src`, keyscore-text `export.rs`의 `voices`·`write_track`, 결정 문서 「내보내기 성부 예산」만 읽고, 테스트 diff를 열기 전에 적었다.

1. 리뷰 1·2 테스트가 바뀌지 않고 통과하는가. 수정을 되돌리면 리뷰 2 테스트가 실패하는가.
2. 새 기준(텍스트가 나르는 내용으로 다시 만든 프로젝트)이 아직 부풀려지는가. 정규 `.ksq`의 노트 한 개는 텍스트 노트보다 훨씬 크다.
3. 어림이 모자라는 입력. `voices`에는 예산과 상관없이 새 성부를 여는 길이 남아 있다(「모든 성부의 커서가 시작보다 `MAX_DRIFT` 넘게 앞서」). 한 자리에 사건이 몰리면 성부가 사건 수 / 8쯤 열리고 각자 클립 시작부터 쉼표를 쓴다. 어림은 16개를 넘는 성부를 예산 하나로만 센다.
4. 셋잇단, 화음 타이(음 128개 × 16조각), 따옴표 가사, 같은 이름 트랙, 1/64 박자표, 성부 17개 경계.
5. 반대로 어림이 노트마다 512바이트 넘게 잡고, 노트가 16개를 넘는 트랙은 온음표마다 약 340바이트를 잡는다. `.ksqz`는 압축된 파일 바이트의 256배가 상한이라, 잘 압축되는 평범한 곡이 거부될 수 있다.
6. 어림 전 단계(합친 클립, 다시 만든 프로젝트 직렬화)의 시간·메모리.
7. 특수 파일 판정이 `fs::metadata`(링크를 따라감)의 `is_file`이다. `/dev/stdout`이 일반 파일로 돌려져 있으면 일반 파일로 보고 `/dev/fd`에 임시 파일을 만들려 할 것이다.
8. `/dev/null`·FIFO를 가리키는 심볼릭 링크, 쓰는 도중 실패(EPIPE), 일반 파일은 여전히 이름 바꾸기인가.
9. 구현자 FIFO 테스트가 하드 링크를 쓰기 전용으로 열어 막힘을 푸는 방식이 멈출 수 있는가.
