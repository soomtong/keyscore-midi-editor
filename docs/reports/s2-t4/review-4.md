## 지적

### 1. 감싸지 않은 항목의 가려진 키 등가물이 그대로 그려진다 (수정)

`action_item`은 네이티브 키 등가물이 맨 키일 때만 감싼다(`wrap`). 네이티브 키가 Cmd·Ctrl 조합이지만 사용자 키맵이 그 키를 다른 명령에 걸어 Normal에서 가려지면, `effective_keys`는 None(또는 다른 키)이어서 제목에는 아무것도 붙지 않고, 항목은 감싸지지 않으므로 macOS가 가려진 키를 그대로 그린다. 눌러 보면 다른 명령이 실행된다. review-3 지적 2와 같은 종류이고, review-3 제안 5와 report의 「리뷰 3 대응」이 이 경로(감싸지 않은 항목)를 닫았다고 적었으나 테스트는 프리셋만 본다(`(None, None, _)` 경우를 통과시킨다). KM-13(메뉴의 단축키 = 실제 단축키)에 어긋난다.

재현: 기본 프리셋에서 `edit::Join`(합치기)의 키는 `cmd-j`다. 사용자 키맵에서 `cmd-j`를 `view::ToggleKeyboard`에 걸면 「합치기」 항목에 ⌘J가 그려지지만 ⌘J는 건반 뷰를 토글한다(`effective_keys(합치기)`는 None).

~~~rust
// tests/review_s2_t4_r4.rs의 user_keymap_reload_keeps_menu_keys_correct에서 뺀 지도
// r#"[{"bindings": {"cmd-j": "view::ToggleKeyboard", "x": "view::ToggleKeyboard"}}]"#
// 결과: "합치기: 누를 키 없음, 보이는 키 None Some(cmd-j)"
//       "합치기: 거짓 등가물 cmd-j(Normal에서 다른 명령), 누를 키 None"
~~~

고칠 방향(범위가 좁다): 네이티브 키 등가물이 있고 Normal 경로에서 그 명령을 실행하지 않으면(`effective_keys`와 같은 `bindings_for_input` 검사) 맨 키가 아니어도 감싸 키 등가물을 없앤다. 감싸지 않은 항목은 네이티브 키가 실제로 동작하는 경우로 제한된다. 회귀 테스트는 위 지도를 `review_s2_t4_r4.rs`의 핫리로드 테스트에 되돌려 넣는다.

## 제안 (차단 아님)

1. 기본 프리셋의 「가사 분배」(`lyric::Distribute`)는 `Lyric` 컨텍스트 전용 `cmd-v`라 편집 메뉴에서 「붙여넣기」와 같은 ⌘V가 그려진다. Lyric 컨텍스트에서는 사실이고 e0fdeb1 이전과 같다. 위 수정(Normal 경로 검사)을 그대로 적용하면 이 항목의 ⌘V도 사라진다. 그것이 의도(메뉴는 Normal 기준)면 같은 수정이 처리하고, 아니면 결정 요청이 필요하다. 테스트(`review_s2_t4_r4.rs`)는 이 항목만 예외로 둔다.
