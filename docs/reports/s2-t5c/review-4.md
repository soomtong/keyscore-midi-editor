## 1. 코드만 읽고 적은 「내가 검사할 것」

`git show b4f056b`, `window.rs`의 `focus_document_on_press`·`text_input_focused`, `track_list.rs`의 목록 처리기를 읽고 테스트를 열기 전에 적었다.

1. 새 처리기는 「안쪽이 받았고(`default_prevented`) 포커스가 입력란이면 건너뜀, 아니면 문서로」다. 오른쪽·가운데 버튼으로 겹 바깥 버튼·토글·메뉴 버튼을 누르면 버튼이 포커스를 가져가지만 입력란은 아니므로 문서로 돌아오는가. 두 프리셋(Default `m`, Vim `shift-m`)에서.
2. 왼쪽 버튼으로 겹 바깥 버튼을 누를 때는 버튼이 포커스를 받지 않고 `prevent_default`만 하므로 고치던 입력란이 포커스에 남고 처리기는 건너뛴다. 입력란을 끝내는 일은 버튼의 클릭 처리기(트랙 목록은 자체 왼쪽 처리기)가 하는데, 인스펙터·트랜스포트 버튼에서도 고치던 입력란이 끝나고 모드 키가 사는가.
3. 입력란의 왼쪽·오른쪽 클릭: 입력란이 포커스를 받은 뒤 처리기가 빼앗지 않는가(`text_input_focused`가 입력란 컨텍스트를 보는 방식이 모든 입력란과 `Select` 검색란에서 맞는가).
4. 팝업 메뉴(색·채널·포트·키·모드)와 프로그램 `Select`: 버튼 왼쪽 클릭 뒤 처리기가 포커스를 옮겨 메뉴·목록을 닫지 않는가. 고르기와 검색이 되는가.
5. 고치는 중인 입력란 A가 있을 때 입력란 B를 오른쪽으로 누르면 왼쪽 클릭과 같은가.
6. 패널의 빈 자리 클릭(고치는 중)은 취소하고 모드 키가 사는가. 트랜스포트 바 줄(`top`)에 처리기가 달려 새 회귀가 없는가.
