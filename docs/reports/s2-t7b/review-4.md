## 1. 코드만 읽고 적은 「내가 검사할 것」

`git show fa5c697`의 `autosave.rs`만 읽고 적었다.

1. `remove_dead_locks`의 `old` 조건: 수정 시각 1분(`STALE_TEMP_AGE`) 이상만 지운다. `old`가 `&&`의 맨 앞이라 막 생긴 잠금 파일은 `session_alive`로 잠깐 잠그지도 않는가. 살아 있는 세션의 잠금 파일은 쓰지 않으니 1분 뒤 「오래됨」이 된다. 그때는 `session_alive`만 지킨다. 그 판정이 그대로 일하는가.
2. 1분 조건의 대가: 크래시 뒤 1분 안에 다시 띄워 [버리기]하면 그 세션의 잠금 파일은 남는다. 언제 지워지는가(리뷰 2 B4의 의도).
3. `init`의 재시도: `try_lock` 실패는 `?`로 곧장 `None`(재시도 없음). `same_inode`가 거짓일 때만 다시 만든다. 남이 막 생긴 파일을 잠그거나 지우는 길이 아직 남는가.
4. `recover`의 `claimed` 건너뛰기: 검사(`claimed`)와 잠금(`claim`) 사이가 원자적이지 않고, 잠금 실패는 여전히 무시하고 창을 연다. `discard`는 `claimed`를 보지 않는다.
5. `remove_generation_temps`: 접두 `<키>.ksq.tmp-`가 이웃 키(예 `123-1`과 `123-12`)의 임시 파일을 지우지 않는가. [복구]에서 지우는 때가 그 창의 첫 쓰기 전인가.
6. 메타 → 내용 rename: 첫 쓰기에서 내용 rename이 실패하면 메타를 지운다. 두 rename 사이에 크래시하면 「내용 없는 메타」가 남는다. `scan`은 `.ksq`만 훑어 그것을 보지 않고, `remove_dead_locks`는 모든 `.json`의 세션을 「쓰는 중」으로 센다.
7. 메타 → 내용 순서에서 다른 실행이 두 rename 사이를 읽으면: 메타(새 회차, 살아 있는 세션)와 내용(옛 회차). 살아 있는 세션이라 건너뛴다. 사이에 크래시하면 옛 회차 내용을 복구한다(앞 순서에서는 새 내용 + 옛 메타).

## 6. 실시간·에러 경로

- 스케줄러 경로의 할당·락·로그: 없음. 바뀐 곳은 UI 스레드와 백그라운드 쓰기뿐이다.
- 제품 코드의 `unwrap`/`expect`: 더한 것 없음.
- 에러가 삼켜지는 곳
  - `remove_generation_temps`, 잠금 파일 지우기의 실패 무시(리뷰 1~3과 같은 성격).
  - `init`: `try_lock` 실패는 재시도 없이 잠금 없는 세션이 된다(`autosave.rs:144`). 막 생긴 파일을 남이 잠그는 길은 `old` 조건으로 닫혔다. 시계가 그 틈에 1분 넘게 앞으로 뛸 때만 열린다. 관찰로만 둔다.
  - `recover`: `claim`의 `try_lock` 실패는 여전히 무시하고 창을 연다(`autosave.rs:578-580`). 지적 3.

## 이월

판정에 넣지 않는다. S2-T7c 또는 S2 출구 이월 후보.

- 끝난 세션 잠금 파일 정리는 [복구]·[버리기] 때만 돈다. 바뀐 창 없이 크래시한 세션(저장본 없음)의 잠금 파일은 시트가 뜨지 않아 지울 기회가 없다. 1분 조건 탓에 크래시 뒤 곧 다시 띄워 [버리기]한 세션의 잠금 파일도 다음 시트 때까지 남는다(시도 2). 시작 때 오래된 끝난 세션 잠금 파일을 지우는 정리가 있으면 둘 다 닫힌다. 리뷰 2 제안 3 수정의 범위 밖이던 갈래다.
- `init`의 `try_lock` 실패 재시도 없음(6절 관찰).

## 부록 A. 실패하는 재현 테스트

`crates/keyscore-app/tests/review_s2_t7b_r4.rs` 끝에 그대로 붙여 넣으면 같은 파일의 도우미(`start`, `autosave_dir`, `plant_dead`, `edited`, `age`, `names`, `launch_with_recovery`, `answer`)와 `use`로 컴파일된다. `cargo test -p keyscore-app --test review_s2_t7b_r4 review_r4_d1`로 `9765b71`에서 실패하는 것을 확인했다(남은 파일 `["o.json", "session-<이 실행>.lock", "session-dead-o.lock"]`). 메타만 있는 `o`는 첫 쓰기의 메타 rename 뒤 내용 rename 전에 끝난 세션의 상태를 파일 조작으로 흉내 낸다.

~~~rust
// ---------------------------------------------------------------- 부록 A: 깨뜨린 시도

/// D1. 첫 쓰기에서 메타 rename 뒤 내용 rename 전에 끝난 세션은 메타만 남긴다. [버리기] 뒤에도 그 메타와 그 세션의
/// 잠금 파일이 남는다(메타가 세션을 「쓰는 중」으로 붙잡는다).
#[gpui_kit::test]
fn review_r4_d1_orphan_meta_from_crash_between_renames(cx: &mut TestAppContext) {
    start(cx, "orphan-meta");
    let auto = autosave_dir(cx);
    plant_dead(&auto, "o", &edited("O"));
    std::fs::remove_file(auto.join("o.ksq")).unwrap();
    let o_lock = auto.join("session-dead-o.lock");
    std::fs::write(&o_lock, "").unwrap();
    age(&o_lock, Duration::from_mins(10));
    plant_dead(&auto, "k", &edited("K"));
    launch_with_recovery(cx);
    answer(cx, "버리기");
    let left = names(&auto);
    assert!(
        !left.iter().any(|n| n == "o.json" || n == "session-dead-o.lock"),
        "끝난 세션의 메타만 있는 저장본과 그 잠금 파일이 남았다: {left:?}"
    );
}
~~~
