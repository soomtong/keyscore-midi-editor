# 적대적 리뷰: S1-T3 MIDI 1.0 인코딩과 다운스케일 (리뷰 3회차)

- 리뷰어 세션: 구현자·계획자·1·2회차 리뷰어와 다른 새 서브 에이전트 세션. 구현 맥락을 물려받지 않았다.
- 대상 커밋: `2ea6827`(벤드 변환 이월을 S6-T1로), `c02cc19`(S1-T6·S1-T4 이월), `679e16a`(`InvalidMessage` 문서·표시 문자열), `2488a22`(할당 테스트의 그룹 생성), 그리고 `1f3cb4a`의 대응 기록. 범위는 `git diff 9af2046 HEAD`뿐이다. 인코더 본체와 `Group`은 다시 보지 않았다.

## 1. 코드만 읽고 적은 「내가 검사할 것」

diff의 제품 코드(`error.rs`)와 단계 파일을 먼저 읽고 아래를 적은 뒤 테스트 변경(`encode_alloc.rs`)을 읽었다.

1. 리뷰 1·2 테스트 파일(`review_s1_t3.rs`, `review_s1_t3_r2.rs`)이 리뷰 2 이후 바뀌지 않았는가. 다른 테스트가 지워지거나 `#[ignore]`되지 않았는가.
2. `encode_alloc.rs`에서 그룹을 센 구간 밖으로 옮긴 것이 할당 검사를 약하게 하지 않는가. 그룹 1 생성 실패가 이제 드러나는가.
3. `InvalidMessage`의 새 문서가 그 변형을 돌려주는 모든 곳을 덮는가. 표시 문자열을 바꿔서 문자열에 기대던 호출부·테스트가 깨지지 않는가.
4. 벤드 변환 이월 위치(S6-T1)가 REQ CTL-4·CTL-5·CTL-6과 맞고, 그보다 앞서 같은 결정이 필요한 Task가 없는가.
5. S1-T6 이월(벨로시티 0 Note On을 Note Off로 읽음)이 IO-2·CTL-10의 「보존」과 충돌하지 않고, 인코더가 내보내는 것과 모순되지 않는가.
6. S1-T4 이월(스케줄러는 `Midi1Message::ump(Group)` 워드만 송신)이 S1-T4 범위(패닉, MIDI Clock, chase)를 막지 않는가.
7. 대응 기록(`report.md`)이 실제 커밋과 맞는가.
