# 결정 요청: 키 시퀀스 대기 시간(KM-5 「설정 가능」)

- 날짜: 2026-10-17
- 상태: 결정됨(A)
- 관련: REQ KM-5(멀티키 시퀀스, 대기 시간 기본 1 s, 설정 가능), 9.1(GPUI는 gpui-kit이 고정한 스냅샷), S2-T2

## 상황

GPUI(gpui-pre 0.3.8)는 멀티키 바인딩(`g g`)을 직접 지원한다. 대기 중인 입력은 상수 `PENDING_INPUT_TIMEOUT`(1초) 뒤에 짧은 바인딩으로 확정된다(`gpui-pre-0.3.8/src/window.rs`). 이 값을 바꾸는 API는 없다.

KM-5의 「기본 1 s」는 그대로 맞는다. 「설정 가능」을 지키는 방법은 아래 셋이다.

## 선택지

- A. v1은 GPUI의 1초를 쓴다. 「설정 가능」은 미루고 REQ KM-5 문구에 「v1은 1 s 고정」을 적는다. 설정 화면(S2-T6)에는 이 항목을 두지 않는다.
- B. 시퀀스를 앱이 직접 맞춘다. 키 입력을 캡처 단계에서 가로채 대기 상태·타이머를 앱이 들고, 맞으면 Action을 직접 디스패치한다. GPUI 바인딩에는 단일 키만 둔다.
  - 대기 시간을 바꿀 수 있다.
  - 대신 GPUI의 메뉴 단축키 표시, `bindings_for_action`, 컨텍스트 우선순위를 시퀀스에 대해 앱이 다시 만들어야 한다. 버그가 들어올 자리가 크다.
- C. gpui-pre를 고쳐 쓴다(포크). REQ 9.1(고정 스냅샷)과 부딪친다.

## 권고

A. vim 프리셋의 `g g`·`d a c` 같은 시퀀스는 1초로 충분히 쓸 수 있다(Zed·VS Code vim 확장의 기본값과 같은 범위다). B는 키맵 엔진의 핵심 경로를 GPUI 밖으로 옮겨 S2-T2의 위험을 크게 키운다. 요구가 생기면 S8에서 B를 다시 본다.

## 결정

A(2026-10-17, YoungTaek). v1은 GPUI의 1초를 쓰고 「설정 가능」은 미룬다. REQ KM-5 문구에 「v1은 1 s 고정」을 적는다(에이전트가 고침).
