## 상황

리뷰 2에서 원자적 쓰기(임시 파일 + rename)가 `-o /dev/null`, `-o /dev/stdout`, FIFO를 망가뜨린다는 지적이 나왔다. 그 뒤로 특수 파일은 그대로 열어 쓰는 분기를 두었다. 이 분기는 커널의 경로 해석(링크, `..`, 끝 `/`·`/.`, `/dev/fd`, 링크 한도)을 도구가 다시 흉내 낸다. 그래서 리뷰 3부터 8까지 매 회차가 새 경계를 찾았다.

리뷰 8에서는 두 가지가 나왔다.
- 링크 35개 사슬 끝의 FIFO가 일반 파일로 바뀌었다. 커널 한도는 32인데 도구 한도는 40이다.
- 분류와 열기 사이에 링크를 바꾸면 다른 볼륨의 같은 inode 번호 파일에 옛 꼬리가 남았다.

## 선택지

- A. `-o`는 「없는 경로」와 「일반 파일」만 받는다. 언제나 원자적으로 쓴다. 그 밖의 대상은 오류로 끝낸다.
- B. 지금 구조를 유지하고 리뷰 8의 두 건만 고친다.

## 결정

A(사람: 「일반 파일만」).

- `-o` 대상을 링크를 따라가며 확인한다(`fs::metadata`).
  - `NotFound`면 새로 만든다.
  - 일반 파일이면 같은 디렉터리의 임시 파일 → fsync → rename으로 바꾼다. 링크는 core `ksq::write_file`과 같이 대상 파일을 바꾼다.
  - 그 밖의 모든 경우는 종료 1이다. 대상은 건드리지 않는다.
    - 디렉터리, FIFO, 소켓, 장치, `/dev/stdout`, `/dev/fd/N`
    - `NotFound`가 아닌 확인 오류(ELOOP, EACCES, ENOTDIR 등)
- 오류 메시지에서 셸 리다이렉션을 안내한다. 예: `-o 없이 실행하고 > /dev/null 처럼 리다이렉트하세요`.
- 표준 출력(`-o` 없음)은 지금과 같다.
- 특수 파일 직접 쓰기, `/dev/` 분류, 신원 비교 코드는 지운다.
- 리뷰 2–7 테스트 가운데 `-o`로 특수 파일에 쓰기를 기대하던 것은, 이 결정에 따라 「종료 1, 대상 그대로」를 기대하도록 바꾼다. 입력은 바꾸지 않는다. 바꾸는 근거로 이 문서를 커밋 본문에 적는다.
