# 결정 요청: 클립 분할 시 걸친 노트, 노트 벨로시티·피치 오프셋의 해상도

- 관련 REQ: 5.10(클립 규칙, 분할 `/`, 비파괴 트림), 6.1 SEQ-2, SEQ-3, 6.5 M2-1·M2-3, 9.5
- 관련 Task: S0-T2(모델), S0-T6(`.ksq`), S1(송신), S4-T2(분할·합치기·트림)
- 상태: 결정됨 (2026-10-12, 사람)

## Q1. 분할점에 걸친 노트

- 상황: REQ 5.10은 「커서 위치에서 클립 분할」만 정하고, 분할점을 가로지르는 노트를 어떻게 할지 정하지 않는다. 같은 절은 트림을 비파괴로 요구한다(「줄이면 숨겨질 뿐 지워지지 않는다」).
- 선택지: A. 노트는 통째로 왼쪽 클립에 남고, 클립 끝을 넘는 부분은 숨김 꼬리(재생 때 클립 끝에서 잘림). B. 두 노트로 자름. C. 노트가 걸친 지점에서는 분할 거부.
- 결정: A. 분할 뒤 다시 합치면(`Cmd+J`) 원래 노트로 돌아온다.
- 모델에 미치는 영향: 저장된 노트의 불변식은 「노트 시작은 클립 안(0 ≤ 시작 < 클립 길이)」이다. 새로 넣는 노트(`insert_note`)는 끝까지 클립 안이어야 한다. 끝이 클립 길이를 넘는 노트는 분할(이후 트림)로만 생기고, 재생·내보내기에서 클립 끝까지만 울린다(S1·S0-T5·S0-T6에서 반영).

## Q2. 노트 벨로시티

- 상황: SEQ-3은 「벨로시티(0–65535, v1은 7비트 범위만 씀)」이고, M2-1(M)은 「내부 이벤트는 MIDI 2.0 해상도(16비트 벨로시티)로 보관, v1 송신 시 MIDI 2.0 명세의 변환 규칙으로 7비트로 내림」이다.
- 1차 결정(2026-10-12): A(0–127 값을 그대로 담음). 이 질문은 SEQ-3만 인용하고 M2-1을 빠뜨린 채 제시되었다(구현자 과실). S0-T2 리뷰 1에서 M2-1이 드러나 다시 물었다.
- 최종 결정(2026-10-12, 사람): 16비트로 보관한다. 모델·`.ksq`는 16비트 값을 담는다. 계이름 텍스트 `v<0–127>`, UI, MIDI 1.0 송신은 MIDI 2.0 표준 스케일링으로 변환한다(7→16은 min-center-max 확장, 16→7은 오른쪽 시프트). 7→16→7 왕복은 무손실이다.
- 모델에 미치는 영향: `Velocity`는 u16 전 범위를 받는다. `from_midi1`/`to_midi1`이 변환을 맡는다. MIDI 1.0 Note On 벨로시티 0은 Note Off로 읽히므로, 송신 쪽 처리는 S1에서 정한다.

## Q3. 피치 오프셋 해상도

- 상황: SEQ-3은 「음높이(0–127 + 피치 오프셋 ±1옥타브 소수)」다. 단위가 정해져 있지 않다. 구현자가 결정 요청 없이 정수 센트로 정했고, S0-T2 리뷰 1이 지적했다. MIDI 2.0 노트별 피치(M2-3, v1 제외)는 반음 7.25 고정소수다.
- 선택지: A. MIDI 2.0 해상도, i32, 반음의 1/2^25 단위(±12반음 = ±402,653,184). B. 정수 센트, i16, ±1200.
- 결정(2026-10-12, 사람): A. M2-1의 「2.0을 붙일 때 모델과 파일 포맷을 바꾸지 않는다」에 맞춘다.
