# 결정 요청: 스케줄러 스레드의 시각 대기 시스템 콜

- 관련 REQ: 9.2(MIDI 스케줄러 스레드: 「할당, 락, 시스템 콜(MIDI 송신 API 제외)」 금지)
- 관련 Task: S1-T4
- 근거: `docs/reports/s1-t4/review-1.md` 제안 15
- 상태: 결정됨 (2026-10-16, 사람: 「A: 시각 대기는 예외」)

## 상황

스케줄러는 1 ms마다 깨어 다음 이벤트를 예약한다. 깨기 위해서는 시각까지 기다리는 호출이 필요하다(`mach_wait_until`). 이것은 시스템 콜이다. REQ 9.2는 MIDI 송신 API만 예외로 둔다.

## 선택지

- A. 시각 대기(`mach_wait_until`)를 9.2의 예외로 둔다. 스케줄러 루프의 시스템 콜은 MIDI 송신과 시각 대기 둘뿐이다. 실시간 오디오·MIDI 스레드의 일반적인 방식이다.
- B. 대기 대신 바쁜 대기(spin)를 한다. CPU 한 코어를 계속 쓴다.
- C. CoreMIDI·CoreAudio의 콜백 스레드(외부가 깨워 줌)를 빌린다. 가상 출력에는 그런 콜백이 없어 구조가 크게 바뀐다.

## 구현자 추천

A. 9.2의 의도는 실시간 스레드가 예측할 수 없게 막히는 것을 막는 것이다. 시각 대기는 정해진 시각까지 의도적으로 쉬는 것이라 그 의도와 맞는다. 측정(10분판 NF-3 p99 0.077 ms)도 이 방식에서 나왔다.

## 결정

A. 스케줄러 루프의 시스템 콜은 MIDI 송신 API와 시각 대기(`mach_wait_until`) 둘뿐이다. REQ 9.2 문구(「MIDI 송신 API 제외」)에 시각 대기를 더하는 일은 사람이 REQ를 고칠 때 반영한다.

- 후속 반영(2026-10-17): 개발 단계 문구 수정 승인(`2026-10-17-req-wording-approval.md`)에 따라 REQ 9.2 표의 금지 칸에 시각 대기 예외를 적었다.
