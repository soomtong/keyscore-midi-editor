# 키보드 중심 MIDI 시퀀서 요구사항 문서 (가칭 KeyScore)

Oct 11, 2026 · @soomtong

## 1. 개요

KeyScore는 피아노를 치지 못하는 사람이 **컴퓨터 키보드만으로** 악보를 빠르게 입력하고, 그 결과를 같은 Mac에서 스탠드얼론으로 돌아가는 신디사이저에 MIDI로 보내는 macOS 전용 시퀀서다. UI는 Rust 그래픽 프레임워크 [GPUI](https://www.gpui.rs/)로 작성한다.

**대상 사용자**

- 건반 연주 경험이 없거나 적지만 곡을 만들고 싶은 작곡·편곡 입문자
- 타이핑이 빠르고 마우스 조작을 싫어하는 프로그래머·트래커(tracker) 사용자
- 하드웨어·소프트웨어 신디사이저를 이미 가지고 있고, 그 음색으로 시퀀스를 돌리고 싶은 사람

**핵심 가치 제안**

1. 마우스 없이 입력·편집·재생·저장까지 모든 작업이 키보드로 끝난다.
2. 리듬 게임처럼 메트로놈에 맞춰 키를 누르면 연주 타이밍이 그대로 기록된다(시퀀스 입력 모드).
3. 타이밍 감각이 없어도 스텝 입력으로 한 음씩 정확한 길이와 높이를 찍을 수 있다.
4. 앱은 소리를 만들지 않는다. 같은 컴퓨터에서 스탠드얼론으로 돌고 있는 신디사이저가 잡을 수 있는 **가상 MIDI 포트**를 내고, 모든 소리는 그 신디가 낸다. v1은 MIDI 1.0으로 보내고, MIDI 2.0(UMP)은 이후 버전에서 붙인다.
5. 곡은 모던 DAW처럼 **선형 트랙 위의 클립**으로 구성한다. 노트는 클립 안에 살고, 클립은 타임라인에서 옮기고 복제하고 자른다.

**비교 대상**: 트래커(Renoise, OpenMPT), 악보 편집기(MuseScore, LilyPond), DAW의 피아노롤(Ableton, Logic). KeyScore는 트래커의 키보드 중심성과 피아노롤의 직관성 사이에 자리 잡고, 오디오 엔진을 아예 두지 않는다. 하드웨어 시퀀서가 MIDI 케이블로 음원 모듈을 울리듯, KeyScore는 가상 MIDI 포트로 같은 컴퓨터의 소프트 신디를 울린다.

## 2. 범위

v1.0은 **MIDI 시퀀싱과 외부 신디 출력**에 집중하고, 오디오 녹음·믹싱·플러그인 호스팅은 범위 밖이다.

| 구분 | 항목 |
| --- | --- |
| 포함 | 멀티트랙 MIDI 시퀀싱(선형 트랙 + 클립 타임라인), 4가지 키보드 입력 모드, **AI 모드(외부 LLM API로 프롬프트에서 클립 생성·이어쓰기·변주·가사, 5.12절), 가사(노트별 음절, 가사 모드, SMF Lyric 왕복, 5.15절)**, **컨트롤러 레인·Controller 모드(벨로시티·CC·피치 벤드를 마우스로 그림, 5.9절)**, 가상 MIDI 출력 포트 생성(같은 Mac의 스탠드얼론 신디가 입력으로 선택), CoreMIDI 출력 포트 선택, MIDI 1.0 출력, MIDI 메트로놈·시각 메트로놈, MIDI Clock·Start/Stop 송신, SMF(.mid) Type 0/1 입출력, 자체 프로젝트 파일, 퀀타이즈, 되돌리기/다시 실행, 키맵 커스터마이즈 |
| 비포함 (v1.0) | MIDI 2.0(UMP) 송신, 내장 사운드 모듈·오디오 출력 일체(앱은 소리를 내지 않는다), 로컬에 번들된 AI 모델(외부 API만 사용), 오디오 트랙 녹음, 오디오 이펙트·믹서, MIDI-CI, 협업·클라우드 동기화, 링크된 클립(에일리어스) |
| 이후 고려 | MIDI 2.0 출력(16비트 벨로시티·노트별 피치), 링크된 클립, 루프 클립, AI 모드의 로컬 모델(Ollama 등 OpenAI 호환 엔드포인트는 v1에서도 설정으로 가능) |
| 계획 없음 | 외부 MIDI 키보드 입력, 오선보 뷰, VST3/CLAP/AU 플러그인 호스팅, 스크립팅. 요청이 와도 제품 방향(키보드 입력 + 외부 신디)과 맞지 않아 넣지 않는다 |

**플랫폼**: macOS 전용(macOS 14 Sonoma 이상, Apple Silicon 우선). CoreMIDI가 가상 포트 생성과 UMP(MIDI 2.0)를 모두 네이티브로 지원하므로 플랫폼 추상화 계층을 두지 않는다. Linux·Windows는 범위 밖이며, GPUI가 두 플랫폼을 지원하더라도 이식은 별도 결정으로 미룬다.

**확정된 결정 (설계 인터뷰 1라운드)**

| 주제 | 결정 |
| --- | --- |
| Sequence 모드 본류 | 미리 적기(pre-pitched)가 주 경로, 직접 치기는 보조. 온보딩은 미리 적기를 먼저 보여 준다 |
| 미리 적기의 소스 | 같은 클립에 Step으로 찍어 둔 노트의 음높이 순서. 녹음하면 시작·길이를 제자리에서 덮어쓴다. 타격이 많으면 남는 타격 무시, 적으면 남은 노트는 원래 자리 유지(열 끝에서 자동 정지, 상태줄에 n/m). `Ctrl+음` 화음은 한 항목 |
| Sequence 녹음 undo | 테이크 전체가 한 단위. `Shift+Tab`(테이크 버리기)과 `Cmd+Z`는 같은 결과 |
| 녹음 후 자동 퀀타이즈 | 기본 켬: 현재 길이 코드 그리드에 강도 100%. 설정으로 끔. `q`는 수동 재적용 |
| 판정 임계값 | 보정 후 기준 Perfect ±15 ms, Good ±40 ms, 밖은 Early/Late. 느슨함/보통/엄격 설정, 기본 보통 |
| 메트로놈 | 재생 중은 토글에 따름. Sequence 녹음 중과 카운트인은 항상 켬 |
| 조성 | v1은 프로젝트 전역 조성 하나(없음 가능). 장조·단조 12개씩 + 없음. 전조·클립별 조성·선법은 이후. 트랜스포트에 조성 필드 |
| 조성 표시 | 조성이 있으면 피아노롤·건반 뷰에서 조성 안 음을 밝게, 밖 음을 어둡게(끌 수 있음) |
| 템포·박자표 변화 | v1 UI는 곡 전체 하나씩. 모델은 맵을 가지며 SMF의 변화는 보존만(편집 불가) |
| 새 프로젝트 기본값 | 트랙 2개(Lead ch1, Drums ch10), 템포 120, 4/4, 조성 없음, 빈 클립 없음 |
| 클립 늘리기 | 빈 공간 확장. 반복은 `r` |
| Step 모드 undo | 노트 하나 = undo 한 단위. 세션 묶음 없음(연속 같은 조작만 묶음) |
| 옥타브 키 | `[` `]` 정식, `Z`/`X`는 건반형 별칭. 둘 다 유지 |
| 계이름 텍스트 | 공통 MML 부분집합 + 자체 확장의 KeyScore 자체 문법(5.14절). 다른 방언은 가져오기 시 느슨하게 해석 |
| 텍스트와 키 입력의 숫자 | 서로 다른 문법을 유지. 텍스트는 MML 관례(뒤 숫자 = 길이, `o` 옥타브), 키 입력은 앞 코드 = 길이·뒤 숫자 = 옥타브. UI에 한 줄 안내 |
| AI 비용 | 사용자 OpenRouter 키만. 번들 키 없음 |
| 프롬프트 템플릿 언어 | 시스템·과제 템플릿은 영어, 사용자 한 줄은 어느 언어든. 템플릿에 "요청은 한국어일 수 있다" 명시. UI에 한국어 주석 |
| 어시스트 트리거 | 마디 완료 + 유휴(기본 1.5 s, 0.5–5 s 설정). 응답 2 s 초과는 폐기 |

| MIDI Clock·Start/Stop | 기본 끔. 설정 > MIDI 출력에서 포트별로 켬 |

**추가 결정 (4라운드)**: 가사는 v1에 포함한다(5.15절, LYR-1\~7 M). 키보드 중심 작업에서 가사 입력은 자연스러운 흐름이며, 멜로디를 쓸 때 가사가 있으면 곡의 일관성에 도움이 된다. AI 어시스트는 가사와 멜로디를 함께 다룬다. 가사 모드는 앱에서 유일한 IME 문자 입력 모드이며(KM-7 예외), 가사는 외부 신디로 송신되지 않는다.

## 3. 용어 정의

| 용어 | 정의 |
| --- | --- |
| 틱 (tick) | 시퀀서 내부 시간 단위. PPQ(Pulses Per Quarter note) 960 고정 |
| 스텝 (step) | 스텝 입력 모드에서 커서가 한 번에 전진하는 길이. 기본 4분음표, 길이 코드로 변경 |
| 노트 이벤트 | 클립 안의 (시작 틱, 길이, 음높이, 벨로시티) 묶음. 시작 틱은 클립 시작 기준 |
| 클립 | 트랙 타임라인 위의 연속 구간(시작 틱, 길이). 노트를 담는 유일한 그릇이며 같은 트랙의 클립은 겹치지 않는다. 옮기고, 복제하고, 자르고, 합칠 수 있다 |
| 트랙 | 하나의 MIDI 목적지(포트·채널)에 묶인 선형 타임라인. 클립이 그 위에 놓인다 |
| 배치 뷰 | 트랙×시간 격자에 클립을 블록으로 보이는 화면(DAW의 arrangement view). 피아노롤과 `ga`로 오간다 |
| 피아노롤 뷰 | 클립 하나의 안쪽. 세로 음높이, 가로 틱. 앞뒤 클립은 흐리게 보인다 |
| 입력 커서 | 현재 입력 위치(틱)와 현재 옥타브·길이를 가진 상태 |
| 레이턴시 보정 | 시퀀스 입력 시 키 입력 시각에서 사용자의 평균 반응 지연을 빼는 오프셋 |
| 가상 MIDI 포트 | 앱이 CoreMIDI에 등록하는 가상 소스. 같은 Mac의 다른 앱(스탠드얼론 신디)이 MIDI 입력 장치로 선택한다 |
| 스탠드얼론 신디 | DAW 없이 단독 실행되는 소프트웨어 신디사이저(예: Vital, Surge XT, Pianoteq, Dexed). KeyScore의 유일한 음원 |
| UMP / MIDI 2.0 | Universal MIDI Packet, MIDI 2.0의 패킷 형식. v1 범위 밖이며 모델만 그 해상도를 보관한다 |
| SMF | Standard MIDI File (.mid). MIDI 1.0 기반 교환 포맷 |

## 4. 핵심 디자인 원칙

**P1. 키보드가 유일한 1급 입력 장치다. 그러나 모든 기능은 화면에 보인다.** 모든 기능은 키 바인딩을 가진다. 마우스는 보조 수단이며, 마우스로만 가능한 기능은 설계 결함으로 간주한다. 동시에 모든 기능은 메뉴바·패널·버튼·설정 화면 가운데 적어도 한 곳에 **눈에 보이는 UI**로 존재한다(7.6절). 문서에 나오는 `:assist on` 같은 표기는 명령 팔레트에서 타이핑으로 부르는 지름길이지, 그 기능의 유일한 경로가 아니다 — vim의 ex 명령처럼 "외워야 쓰는" 기능은 두지 않는다. 키맵은 GPUI의 `Action` + `KeyBinding` 체계를 그대로 쓰고, 사용자가 JSON으로 덮어쓸 수 있다. 유일한 예외는 벨로시티·CC 곡선 편집(5.9절)으로, 연속값 곡선은 마우스로 그리는 쪽이 낫다고 판단해 거기서만 마우스를 1급으로 둔다.

**P2. 모달 편집(vi 방식).** Normal(이동·선택), Step(스텝 입력), Sequence(리듬형 입력), Play(키보드 시뮬레이션) 네 입력 모드에 AI(프롬프트로 생성, 5.12절)를 더한 다섯 모드를 둔다. 모드는 화면 하단 상태줄에 항상 표시되고, `Esc`는 어느 모드에서든 Normal로 돌아간다.

**P3. 음높이 입력은 건반 레이아웃이 기본이고, 계이름 레이아웃을 대안으로 둔다.** (a) **건반 레이아웃(기본)**: 홈 로우 `A S D F G H J K L`이 흰건반 C D E F G A B C D, 윗줄 `W E T Y U O P`가 그 사이 검은건반(Ableton·FL Studio와 같은 배치). 숫자 줄과 Z 줄은 비워 두어 길이 코드·명령에 쓴다. (b) **계이름 레이아웃**: `c d e f g a b` 글자로 음을 치고 `#`/`-`로 반음, 숫자로 옥타브(LilyPond·MML 전통). 두 레이아웃은 글자가 겹치므로 설정에서 하나를 고르며, 첫 실행에서 건반형을 보여 주고 계이름형으로 바꿀 수 있다고 안내한다.

**P4. 타이밍은 틱으로 기록하고 소리는 밖에서 난다.** 시퀀서 모델은 오디오와 무관한 순수 데이터(틱 기반 이벤트 리스트)다. 스케줄러가 그 이벤트를 시각이 붙은 MIDI 메시지로 바꿔 포트로 내보내는 것이 앱이 하는 전부이며, 오디오 스레드·오디오 장치·사운드폰트는 존재하지 않는다.

**P5. 저지연이 UI보다 우선한다.** 키 입력 → MIDI 송신까지 3 ms 이하, 재생 중 송신 지터 0.5 ms 이하를 목표로 한다. 이를 위해 MIDI 스케줄러 스레드는 GPUI 메인 루프와 완전히 분리하고, 락 없는 링버퍼로만 통신한다. 소리까지의 총 지연은 외부 신디의 오디오 버퍼에 달려 있으므로, 앱은 자기 몫(송신까지)만 책임지고 측정 방법을 제공한다.

**P6. 틀려도 빨리 고친다.** 리듬형 입력은 반드시 틀린 타이밍을 낳으므로, 입력 직후 퀀타이즈·한 음 뒤로·재입력이 한 키로 가능해야 한다. 되돌리기는 무제한이고 입력 세션 단위로 묶인다.

**P7. 앱은 악기가 아니라 MIDI 인터페이스다.** 하드웨어 시퀀서가 MIDI OUT 단자를 내듯, KeyScore는 CoreMIDI에 가상 MIDI 출력 포트를 등록한다. 같은 Mac의 스탠드얼론 신디사이저는 그 포트를 입력 장치로 고르기만 하면 된다. 음색 확인·메트로놈·노트 미리듣기까지 전부 그 포트를 통해 외부 신디가 낸다. v1은 MIDI 1.0으로 보내되, 모델은 16비트 벨로시티를 보관해 MIDI 2.0 출력을 이후에 손실 없이 붙일 수 있게 한다.

**P8. vim은 원리만 빌리고 글자는 빌리지 않는다.** 이 앱의 사용자는 대부분 vim을 모른다. 빌리는 것은 모달 편집, 홈 로우, "선택하고 동작"의 조합 가능성, 되돌리기 단위, 한 키 한 뜻이라는 원리다. `y`·`p`·`dd`·`gg` 같은 글자 배정은 빌리지 않는다. 기본 키맵의 글자는 **영어 동사·음악 용어의 첫 글자나 모양**에서 고르고(`r` repeat, `/` 자르기, `b` bar, `m` mute, `q` quantize), 모드 전환은 `Enter` 들어가기 · `Esc` 나가기 · `Tab` 다음으로 세 키로 통일한다. 편집은 "선택 → 동작"이 기본이고 vim의 오퍼레이터·텍스트 객체·카운트 접두는 `vim` 프리셋에서만 산다(5.8.1절). 같은 키에 더 좋은 뜻이 있으면 vim 관습을 버린다.

## 5. 입력 모드 상세

네 모드는 같은 노트 이벤트 모델에 쓰기만 하고, 차이는 **시간축을 누가 움직이느냐**다. 스텝은 사용자가, 시퀀스·플레이는 트랜스포트가, 피아노롤은 커서 이동 키가 움직인다.

| 모드 | 시간 진행 | 음높이 결정 | 길이 결정 | 주 사용자 |
| --- | --- | --- | --- | --- |
| Step 입력 | 노트 입력 시 커서가 스텝 길이만큼 자동 전진 | 키 레이아웃 (a)/(b) | 현재 길이 코드 | 타이밍 감각 없는 입문자 |
| Sequence 입력 (리듬형) | 메트로놈에 맞춰 트랜스포트가 실시간 진행 | 키 레이아웃, 또는 미리 적은 음높이 열을 순서대로 소비 | 키를 누른 시각부터 뗀 시각까지 | 리듬은 되지만 건반은 못 치는 사람 |
| Piano Roll 편집 | 커서 이동 키 (`h j k l`, 마디·박 점프) | 커서의 세로 위치 | 선택 영역 길이 조정 키 | 입력 후 수정 작업 |
| Keyboard 시뮬레이션 (Play) | 기록 없음, 즉시 연주만 | 키 레이아웃 | 키를 누른 동안 | 음색·화음 확인 |
| AI (5.12절) | LLM이 클립 단위로 한꺼번에 생성 | 프롬프트·기존 클립·조성에서 LLM이 결정 | LLM이 결정, 앱이 그리드에 맞춤 | 아이디어가 필요하거나 반주를 빨리 깔고 싶은 사람 |

### 5.1 Step 입력 모드

- 진입 `Enter`(커서 위치에서) 또는 `Ctrl+Tab`, 종료 `Esc`. vim 프리셋은 `i`도 받는다. 상태줄에 `STEP ♩ oct4` 형식으로 현재 길이·옥타브 표시. 커서가 클립 밖에 있으면 마디 단위 새 클립을 만들고 시작한다.
- **기본 길이는 4분음표**다. 음 키만 누르면 커서 위치에 4분음표를 쓰고 커서가 그만큼 전진한다. `Space`는 쉼표(커서만 전진), `Backspace`는 한 스텝 뒤로 가며 그 자리 노트를 지운다.
- 길이는 **숫자 한 자리**로 바꾼다: `1` 온음표, `2` 2분, `3` 4분, `4` 8분, `5` 16분, `6` 32분, `7` 64분, `0` 기본값(4분)으로 복귀. 한 번 고른 길이는 다음 입력에도 유지된다(스티키). 상세 문법은 5.6절.
- **`Shift`는 길이를 수정한다**: `Shift+숫자`는 그 길이의 점음표(`Shift+3` = 점4분음표), `Shift+음 키`는 현재 길이의 절반으로 그 음 하나만 입력(한 번만 적용, 스티키 아님). `n`을 음 앞에 붙이면 셋잇단(`n` = n잇단, 두 레이아웃 모두에서 비어 있는 키).
- 옥타브: `[` `]`로 ±1. 건반 레이아웃은 `A`–`L`이 한 옥타브 + 2음(C4–D5)이고 `Z`/`X`로도 옥타브를 내리고 올린다. 벨로시티는 트랙 기본값(100)으로 고정하고 Step 모드에서 바꾸지 않는다(5.9절).
- 화음: `Ctrl+음 키`는 커서를 전진시키지 않고 같은 위치에 음을 겹친다. 마지막 음은 `Ctrl` 없이 눌러 전진.
- 타이: 음 키 직후 `~`를 누르면 직전 노트 길이를 현재 길이만큼 늘린다(MML `&` 전통).
- 계이름 레이아웃(b)에서는 MML 호환 문법도 그대로 받는다. 예: `c d e f g a b` `c+`(반음 올림) `c-`(내림) `o5`(옥타브 지정) `l8`(기본 길이 8분음표) `r`(쉼표). 텍스트 가져오기(IO-3)에서는 MML의 `l16` 같은 두 자리 숫자를 그대로 해석한다.

```text
// 계이름 레이아웃 입력 예 — 반짝반짝 작은 별 첫 두 마디
o4 l4 c c g g a a g2  f f e e d d c2
```

### 5.2 Sequence 입력 모드 (리듬형)

리듬 게임의 방식을 가져온다: 화면에 박자 그리드가 흐르고, 사용자는 메트로놈과 시각 큐에 맞춰 키를 누른다. 누른 시각과 뗀 시각이 그대로 노트의 시작·끝이 된다.

- 진입 `Cmd+R`(녹음, DAW 관례) 또는 `Ctrl+Tab`. 카운트인 1마디(기본) 후 녹음 시작, 녹음 중 메트로놈은 토글과 무관하게 켜진다. `Esc` 또는 클립 끝(미리 적기는 열 끝)에서 자동 종료. 커서가 클립 밖이면 녹음이 끝난 범위만큼 새 클립을 만든다.
- **음높이 소스 두 가지**:
  1. 미리 적기(pre-pitched, 주 경로): 같은 클립에 Step으로 음높이 열을 먼저 찍어 두고, Sequence에서는 \*\*아무 키(기본 `Space`)\*\*만 박자에 맞춰 누른다. 타격마다 열의 다음 노트(화음은 한 항목)가 그 타이밍·길이로 제자리에서 덮어써진다. 타격이 열보다 많으면 남는 타격은 무시, 적으면 남은 노트는 원래 자리에 남는다. 상태줄에 `12/16`.
  2. 직접: 키 레이아웃으로 음을 치면서 동시에 타이밍도 잡는다.
- 입력 보정: 사용자별 반응 레이턴시를 보정 마법사(10번 탭 평균)로 측정해 자동으로 뺀다. 테이크가 끝나면 현재 길이 코드 그리드에 강도 100%로 **자동 퀀타이즈**(기본 켬, 설정으로 끔). `q`로 다른 설정을 수동 재적용, `Cmd+Z`는 테이크째 되돌림.
- 루프 녹음: 클립 길이만큼 반복 재생하면서 겹쳐 쓰기/덮어 쓰기 선택. 한 번에 한 성부씩 쌓는 흐름을 전제한다.
- 시각 피드백: 보정 적용 후 기준으로 Perfect(±15 ms)·Good(±40 ms)·Early/Late를 색과 모양으로 표시하되, 게임처럼 점수화하지는 않는다. 느슨함/보통/엄격 설정(기본 보통). 목적은 입력이지 평가가 아니다.

### 5.3 Piano Roll 편집 모드

- Normal 모드의 기본 화면. 클립 하나의 안쪽을 세로축 음높이, 가로축 틱으로 보인다. 커서는 (틱, 음높이) 한 칸. 앞뒤 클립의 노트는 흐리게 보이고 편집은 되지 않는다.
- 편집의 기본 흐름은 **선택 → 동작**이다. `Shift+이동`으로 선택을 넓히고, `Delete`로 지우고, `Cmd+C`/`Cmd+V`로 옮기고, `Alt+이동`으로 밀고, 숫자로 길이를 정한다. 키 체계는 5.7절, 전체 키맵은 5.8절.
- 자주 쓰는 편집: `/` 커서 위치에서 분할, `Cmd+J` 선택 노트 합치기(길이 연장), `r` 선택을 바로 뒤에 반복 복제, `e` 커서 노트의 음높이 바꾸기(음 키 하나 입력), `b` 현재 마디 선택.
- 커서가 노트 위로 가면 그 노트를 외부 신디로 짧게 들려준다(설정 "이동 시 미리듣기", 기본 켬). `Enter`는 커서 위치에서 Step 모드로 들어가고, `Esc`는 선택 해제 → 배치 뷰 순으로 한 단계씩 나간다. `v`로 배치 뷰(5.10절)와 오간다.

### 5.4 Keyboard 시뮬레이션 (Play) 모드

- 진입 `Cmd+K`(keyboard) 또는 `Ctrl+Tab`, 또는 하단 건반 뷰의 "연주" 버튼. 종료 `Esc`. 기록 없이 키를 누르는 동안만 현재 트랙의 출력 포트·채널로 노트를 보낸다. 화면 하단에 2옥타브 건반을 그려 어느 키가 어느 음인지 보여 준다.
- 출력 대상 전환: `Tab`/`Shift+Tab`으로 다음/이전 트랙의 출력, `F1`–`F8`로 트랙 1–8 직접, 또는 트랙 목록 클릭. 외부 신디가 어느 포트를 듣고 있는지는 상태줄과 트랙 인스펙터의 포트 이름으로 확인한다.
- 음색 바꾸기: `,` `.`으로 프로그램 체인지 −1/+1 송신, 또는 트랙 인스펙터의 뱅크·프로그램 드롭다운(GM 이름 검색 가능). 외부 신디가 프로그램 체인지를 받지 않으면 신디 쪽에서 음색을 고른다.
- 서스테인 `Shift`(CC64 송신), 옥타브 `[` `]` 또는 건반 뷰의 옥타브 버튼. 벨로시티는 트랙 기본값으로 고정한다(컴퓨터 키보드는 누르는 세기를 모른다).

### 5.5 모드 간 전환 규칙

```text
들어가기 = Enter · 나가기 = Esc · 다음으로 = Tab · 모드 순환 = Ctrl+Tab

  배치 뷰 ──Enter──▶ 피아노롤(Normal) ──Enter──▶ Step
          ◀──Esc───                   ◀──Esc───
  Normal ──Cmd+R──▶ Sequence(녹음)   ──Esc / 클립 끝──▶ Normal
  Normal ──Cmd+K──▶ Play(건반)       ──Esc──▶ Normal
  Normal ──a──────▶ AI 패널          ──Tab(수락) / Esc──▶ Normal

  Esc는 한 단계씩 나간다: AI 고스트 → 선택 → 모드 → 피아노롤 → 배치 뷰
```

어느 모드에서든 `Space`(Normal·Play) 또는 `Cmd+Return`은 재생/정지, `Cmd+.`은 패닉(All Notes Off 전 포트 송신), `Ctrl+Tab`은 모드 순환(5.11절)이다. Step 모드의 `Space`는 쉼표이므로 거기서는 `Cmd+Return`을 쓴다.

### 5.6 숫자·문자 조합 입력 (Step 모드)

한 음의 **길이·음이름·옥타브**를 한 번에 치는 문법이다. 형식은 `[길이][음이름[변화표]][옥타브]`이고 세 자리 모두 생략할 수 있다. 생략한 자리는 커서의 현재 값을 쓴다.

- **앞 숫자 = 길이 코드(한 자리)**. vim의 카운트 접두와 같은 자리다. 두 자리 숫자(`16`)를 치지 않도록 코드 한 자리로 길이를 고른다. `3c`는 4분음표 C, `5g`는 16분음표 G. 코드 표는 아래.
- **`Shift` = 길이 수정자**. `Shift+코드`는 점음표(`Shift+3` = 점4분음표), `Shift+음`은 현재 길이의 절반을 그 음에만 한 번 적용한다. 16분음표를 주로 치다가 32분음표 하나가 필요하면 `Shift+음`으로 끝낸다.
- **뒤 숫자 = 옥타브**(과학적 음높이 표기, 한 자리 0–9). 앞 숫자와 뒤 숫자 모두 한 자리이고 음 키가 사이를 가르므로 `5c4`(16분음표 C4)처럼 섞어도 모호하지 않다. 건반 레이아웃에서는 뒤 숫자가 그 음의 옥타브를 바꾸고 이후에도 유지된다.
- **변화표**(계이름 레이아웃만): 음이름 바로 뒤에 `#` 또는 `+` 올림, `b` 또는 `-` 내림. `4c#4`, `3bb3`. 건반 레이아웃은 검은건반 키를 직접 친다.
- **셋잇단**은 `n`을 음 앞에: `4nc` 셋잇단 8분음표. 세 음이 모이면 자동으로 묶인다. `n`은 두 레이아웃 모두에서 비어 있는 키다.
- **쉼표**: 길이 코드만 치고 `Space` → 그 길이의 쉼표. `3 Space`는 4분쉼표, 코드 없이 `Space`는 현재 길이의 쉼표.
- **확정 시점**: 음 키가 들어온 뒤 옥타브 숫자를 기다리는 시간은 기본 300 ms(설정 가능)다. 그 안에 숫자가 없으면 현재 옥타브로 확정한다. `Enter`나 다음 음 키를 치면 즉시 확정한다. 상태줄에 조합 중인 입력을 `5c_`처럼 보여 준다.
- **스티키 규칙**: 길이 코드와 옥타브는 다음 입력에도 유지된다(MML의 `l`, `o`와 같은 동작). `Shift+음`의 절반 길이만 한 번 적용이다. `0`은 길이를 기본값(4분음표)으로 되돌린다. 기본 길이 자체는 설정에서 바꿀 수 있다.
- **두 레이아웃에서 같은 문법**: 건반 레이아웃은 숫자 줄과 Z 줄을 음에 쓰지 않으므로(P3) 길이 코드와 옥타브 숫자를 그대로 쓴다. 아래 예시는 계이름 레이아웃으로 적었고, 건반 레이아웃에서는 음이름 자리에 해당 건반 키(`c`→`A`, `e`→`D`, `f#`→`T` 등)를 친다.

### 5.7 커서 이동·선택과 선택 노트의 빠른 조작

수식키마다 역할을 하나씩 고정한다. 수식키 없는 키는 **커서**를, `Shift`는 **선택 넓히기**(macOS·DAW 공통 관례)를, `Alt`는 **선택한 노트를 밀기**를, `Alt+Shift`는 **선택한 노트의 길이와 옥타브**를, `Ctrl`은 **큰 단위**를 맡는다. `Cmd`는 7.5절의 표준 단축키 전용이다. `hjkl`과 화살표 키는 모든 조합에서 같은 뜻이며, 화살표만 써도 전부 된다.

| 수식키 | `h` / `←` | `l` / `→` | `j` / `↓` | `k` / `↑` |
| --- | --- | --- | --- | --- |
| (없음) 커서 | 한 스텝 뒤로 | 한 스텝 앞으로 | 반음 아래 | 반음 위 |
| `Shift` 선택 넓히기 | 뒤로 한 스텝 | 앞으로 한 스텝 | 반음 아래까지 | 반음 위까지 |
| `Ctrl` 큰 커서 이동 | 한 마디 뒤로 | 한 마디 앞으로 | 한 옥타브 아래 | 한 옥타브 위 |
| `Ctrl+Shift` 크게 선택 | 한 마디 뒤까지 | 한 마디 앞까지 | 한 옥타브 아래까지 | 한 옥타브 위까지 |
| `Alt` 선택 노트 밀기 | 한 스텝 앞당김 | 한 스텝 미룸 | 반음 내림 | 반음 올림 |
| `Alt+Shift` 선택 노트 길이·옥타브 | 끝을 한 스텝 줄임 | 끝을 한 스텝 늘림 | 한 옥타브 내림 | 한 옥타브 올림 |
| `Alt+Ctrl` 선택 노트 크게 밀기 | 한 마디 앞당김 | 한 마디 미룸 | (예약) | (예약) |

- **선택**: `Shift+이동`으로 넓힌다. 선택이 없으면 `Alt`·`Alt+Shift` 조작은 커서 위의 노트 하나에 적용된다. `Cmd+A` 클립 안 전체, `b` 현재 마디, `Shift+b` 클립 전체, `Esc` 선택 해제. 마우스 러버밴드(7.4절)와 같은 선택 상태를 공유한다.
- **노트 단위 이동**: `n` 다음 노트, `p` 이전 노트, `Shift+n`/`Shift+p` 다음/이전 클립, `Cmd+←`/`Cmd+→` 클립 처음/끝, `Cmd+↑`/`Cmd+↓` 첫/마지막 트랙(macOS의 문서 처음·끝 관례).
- **반복은 키를 누르고 있는 것으로** 한다(OS 키 반복). vim 프리셋에서만 숫자 카운트 접두(`3l`)를 쓰며, 기본 프리셋에서 숫자는 길이 코드다.
- **길이 직접 지정**: 선택 후 길이 코드 한 자리를 누르면 바로 적용된다. `5`는 선택한 노트 전부를 16분음표로, `Shift+3`은 점4분음표로(5.6의 길이 코드와 같은 규칙, `Enter` 불필요).
- **조절 단위**: `Alt+Shift+h/l`의 한 스텝은 Step 모드의 현재 길이와 같다. 상태줄의 길이를 바꾸면 늘임·줄임 단위도 같이 바뀐다.
- **별칭**: `+`/`-`는 `Alt+k`/`Alt+j`, `>`/`<`는 `Alt+Shift+l`/`Alt+Shift+h`와 같다. 한 손으로 치기 편한 쪽을 쓴다.
- **되돌리기 묶음**: 같은 조작을 연속으로 누른 것은 되돌리기 한 번으로 묶인다(`Alt+Shift+l` 다섯 번 → `Cmd+Z` 한 번).

### 5.8.1 vim 프리셋 — 별칭 키맵

`vim` 프리셋은 5.8의 기본 프리셋 위에 아래 별칭을 얹는다. 글자 배정은 vim의 **소문자는 작은 단위, 대문자(Shift)는 큰 단위이거나 반대 방향** 원칙을 따르고, 수식키 체계도 vim식으로 바뀐다: `Shift`가 선택 넓히기 대신 노트 길이·옥타브를 맡고, 선택은 `v`/`V` 비주얼 모드로, 반복은 숫자 카운트 접두로 한다. 오퍼레이터(`d` `y` `c`)와 텍스트 객체(`dac` `yib` `vin`)도 이 프리셋에서만 산다. 기본 프리셋 사용자는 이 절을 읽을 필요가 없다.

### 5.9 벨로시티·컨트롤러는 마우스로 커브를 그린다 (컨트롤러 레인 / Controller 모드)

벨로시티, 모듈레이션(CC1), 그 밖의 CC, 피치 벤드 같은 연속값은 키보드가 아니라 **마우스로 그래프를 드래그해 그린다**. 곡선은 키를 반복해 누르는 것보다 손으로 그리는 쪽이 빠르고 정확하다. 이 영역은 P1(키보드 우선)의 유일한 예외이며, 음높이·길이·위치를 다루는 다른 모드의 키 체계에는 값 조정 키를 두지 않는다.

- **두 가지 화면**: (1) 피아노롤 아래에 접히는 **컨트롤러 레인** — `c` 또는 레인 상단의 접기 화살표로 열고 닫으며 높이를 끌어 조절한다. 노트와 같은 시간축을 공유해 어느 노트의 값인지 바로 보인다. (2) **Controller 모드** — 레인을 화면 전체로 키운 상태, 진입 `Shift+c` 또는 레인의 확대 버튼, 종료 `Esc`. 긴 곡의 CC를 한눈에 그릴 때 쓴다.
- **레인 종류**: 벨로시티(노트별 세로 막대), CC(1 모듈레이션, 7 볼륨, 10 팬, 11 익스프레션, 64 서스테인, 74 컷오프 등 레인 헤더의 드롭다운에서 번호로 추가), 피치 벤드. 한 번에 한 레인을 보이고 `Tab`/`Shift+Tab` 또는 헤더 클릭으로 전환한다. 노트별 피치·압력(MIDI 2.0) 레인은 UMP 송신과 함께 이후.
- **마우스 조작**: 드래그 = 자유 곡선(펜). `Shift+드래그` = 직선(램프). `Alt+드래그` = 시작·끝을 고정하고 가운데를 당겨 휘는 곡선. 더블클릭 = 포인트 추가, 포인트 더블클릭 = 삭제. 벨로시티 막대는 위아래로 끈다. 영역을 긁어 선택한 뒤 위아래로 끌면 전체를 비례 조정, 휠은 선택 영역 미세 조정. 그리는 동안 값이 외부 신디로 바로 송신돼 들으면서 그릴 수 있다.
- **키보드는 보조**: 레인 열기·전환·줌·되돌리기·모드 전환만 키로 한다. 값을 바꾸는 키는 두지 않는다.
- **저장 형식**: CC·벤드는 (틱, 값) 포인트 열로 클립 안에 저장하고 사이는 선형 보간한다. 송신 때 설정 간격(기본 5 ms)으로 샘플링해 MIDI 1.0 7비트(벤드 14비트)로 내보내며, 값이 바뀌지 않으면 보내지 않는다. 벨로시티는 노트 속성(SEQ-3)이다.
- **기본값**: 레인에서 손대지 않은 노트의 벨로시티는 트랙 기본값(100, 트랙 인스펙터의 "기본 벨로시티" 필드에서 변경). CC는 포인트가 없으면 송신하지 않는다.
- **Sequence 모드와의 관계**: 리듬형 녹음은 벨로시티·CC를 기록하지 않는다(컴퓨터 키보드는 세기를 모른다). 녹음을 마친 뒤 레인에서 그린다.
- **우선순위**: 벨로시티·CC·피치 벤드 레인과 마우스 조작은 v1 필수(M). Controller 모드(전체 화면)는 S. 상세 요구사항은 6.7절.

### 5.10 클립과 배치 뷰

곡은 **선형 트랙 위에 놓인 클립**으로 구성한다. 모던 DAW의 arrangement view와 같은 모델이며, 트래커식 패턴 순서표나 클립 런처는 두지 않는다. Normal 모드는 두 뷰를 오간다: 클립 안을 편집하는 **피아노롤 뷰**와 클립을 블록으로 다루는 **배치 뷰**. 전환은 `v`, 배치 뷰에서 클립 위 `Enter`로 안으로 들어가고 `Esc`로 나온다.

**클립 규칙**

- 클립은 (트랙, 시작 틱, 길이)를 가지며 같은 트랙 안에서 겹치지 않는다. 노트의 시작 틱은 클립 시작 기준이라 클립을 옮기면 노트가 함께 간다.
- 클립 밖에서 Step·Sequence 입력을 시작하면 마디 단위로 새 클립이 자동으로 생긴다. 입력이 클립 끝을 넘으면 클립이 마디 단위로 늘어난다.
- 클립을 줄이면 잘린 노트는 숨겨질 뿐 지워지지 않는다. 다시 늘리면 돌아온다(DAW와 같은 비파괴 트림).
- 클립에는 이름과 색을 줄 수 있다. 색은 트랙 색을 기본으로 한다.
- 루프 클립(늘리면 내용이 반복되는 클립)과 링크된 클립(한쪽을 고치면 복제본이 따라오는 에일리어스)은 이후 고려. v1의 복제는 독립 사본이다.

**배치 뷰 키 (Normal 모드 공통 체계를 클립 단위로 적용)**

| 수식키 | `h` / `l` | `j` / `k` | 비고 |
| --- | --- | --- | --- |
| (없음) 커서 | 이전/다음 클립 경계 | 위/아래 트랙 | `Ctrl+h/l`이 마디 단위 |
| `Shift` 선택 넓히기 | 이전/다음 클립까지 | 위/아래 트랙까지 | 러버밴드와 같은 선택 |
| `Ctrl` | 한 마디 뒤/앞 | 맨 위/맨 아래 트랙 |  |
| `Alt` 클립 밀기 | 한 마디 앞당김/미룸 | 위/아래 트랙으로 옮김 | 목적지 채널이 달라지면 경고 |
| `Alt+Shift` 클립 길이 | 끝을 한 마디 줄임/늘림 | (예약) | 비파괴 트림 |
| `Alt+Ctrl` 클립 시작점 | 시작을 한 마디 앞/뒤 | (예약) |  |

- `Shift+이동`으로 클립 선택, `Delete`·`Cmd+X`·`Cmd+C`·`Cmd+V`·`Cmd+D`는 클립 단위. 붙여넣기는 커서 위치에, 겹치면 뒤로 민다. `r`은 선택 클립을 바로 뒤에 반복 복제.
- `/` 커서 위치에서 클립 분할, `Cmd+J` 인접 클립 합치기, `Cmd+T` 새 트랙.
- `Shift+Space`는 커서 클립부터 재생, `Shift+Enter`는 선택 클립 루프 재생.
- 키 반복은 누르고 있는 것으로 한다. `Alt+Shift+l`을 네 번이면 네 마디 늘어난다.
- 마우스로 클립을 러버밴드로 골라 한꺼번에 끌고 늘일 수 있다(7.4절).

### 5.11 Tab 키의 역할

`Tab`은 홈 로우에서 새끼손가락으로 바로 닿는 키이므로 **"확정하고 다음으로"** 한 가지 뜻으로 고정하고 모든 모드에서 자주 쓰게 한다. `Shift+Tab`은 언제나 그 반대(이전으로), `Ctrl+Tab`은 모드 순환이다. 어느 모드에서든 `Tab`이 무언가를 지우거나 값을 바꾸는 일은 없다. 넘어가기만 한다.

| 상황 | `Tab` | `Shift+Tab` |
| --- | --- | --- |
| Normal · 피아노롤 뷰 | 같은 시간 위치의 **다음 트랙**으로(그 트랙의 클립 안으로) | 이전 트랙 |
| Normal · 배치 뷰 | 다음 트랙 | 이전 트랙 |
| Normal · 선택이 있을 때 | 선택을 유지한 채 다음 트랙 — 같은 자리에 붙여 넣는 흐름(`Cmd+C` → `Tab` → `Cmd+V`) | 이전 트랙 |
| Step 모드 | 조합 중인 입력을 **즉시 확정**하고 다음 스텝으로. 조합이 없으면 쉼표 없이 커서만 한 스텝 전진 | 한 스텝 뒤로(삭제 없음, `Backspace`와 구분) |
| Step 모드 · 화음 입력 중(`Ctrl+음`) | 겹쳐 둔 화음을 확정하고 전진 |  |
| Step 모드 · AI 고스트 표시 중 | 고스트를 **다음 마디 끝까지 받아들이고** 그 뒤로 이동(5.12절 어시스트) | 고스트 무시하고 한 스텝 뒤로 |
| AI 패널 · 생성 결과 미리보기 | 결과 전체를 수락 | 이전 후보(재생성 이력)로 |
| Sequence 모드 · 미리 적기 | 열의 다음 음을 **건너뛰기**(틀린 자리를 비워 두고 진행) | 열의 이전 음으로 되감기 |
| Sequence 모드 · 루프 녹음 | 이번 테이크를 확정하고 다음 루프 | 이번 테이크를 버리고 다시 |
| Play 모드 | 다음 트랙의 출력(포트·채널)으로 전환 | 이전 트랙 |
| 컨트롤러 레인 | 다음 레인 | 이전 레인 |
| 명령줄 `:` · 명령 팔레트 | 자동완성 확정 | 이전 후보 |
| 키맵 편집 · 설정 · 대화상자 | 다음 필드(macOS 표준) | 이전 필드 |
| `?` 키맵 오버레이 | 다음 페이지 | 이전 페이지 |

**모드 순환**: `Ctrl+Tab`은 Normal → Step → Sequence → Play → Normal, `Ctrl+Shift+Tab`은 역순. 현재 커서 위치를 유지한 채 모드만 바뀌므로, 피아노롤에서 자리를 잡고 `Ctrl+Tab` 한 번으로 Step 입력에 들어가는 흐름이 `i`와 나란히 존재한다. `Esc`는 여전히 어디서든 Normal로 돌아온다.

**트랙 간 이동의 기준**: `Tab`으로 트랙을 바꿀 때 커서의 시간 위치는 유지하고, 음높이는 그 트랙에서 마지막으로 편집한 음높이로 옮긴다(없으면 C4). 목적지 시간에 클립이 없으면 배치 뷰 기준의 빈 자리에 커서를 두고, 입력을 시작하면 클립이 생긴다(5.10절).

### 5.12 AI 모드 — 외부 LLM으로 클립 생성

사용자가 한 줄 프롬프트를 쓰면 외부 LLM API가 \*\*앱의 계이름 텍스트(MML 호환, IO-3)\*\*로 음악을 돌려주고, 앱이 그것을 파싱해 커서 위치에 \*\*미리보기 클립(고스트)\*\*으로 놓는다. 사용자는 들어 보고 `Tab`으로 받아들이거나 `Esc`로 버리거나 `r`로 다시 생성한다. 진입은 `a`(또는 `:ai`). 모델은 앱에 들어 있지 않고, OpenAI 호환 엔드포인트(상용 소형 모델, 또는 Ollama 같은 로컬 서버)를 설정으로 지정한다.

**왜 계이름 텍스트인가**: 소형 LLM은 JSON 노트 배열보다 `o4 l8 c d e f g4 r4`처럼 짧고 규칙적인 텍스트를 훨씬 안정적으로 낸다. 이미 IO-3로 파서가 있으므로 AI 모드는 새 포맷 없이 입력 경로 하나를 더하는 것이다. 멀티트랙 응답은 트랙마다 한 블록으로 받는다.

**진입과 흐름**

1. Normal에서 `a`(또는 `:ai`)로 AI 패널을 연다. 커서 위치·선택 범위·현재 트랙이 생성 대상이다.
2. 프롬프트 한 줄을 쓴다. 예: `이 멜로디에 어울리는 베이스 8마디`, `4마디 더 이어서`, `같은 리듬으로 변주`, `더 느리고 슬프게`.
3. 앱이 컨텍스트를 묶어 보낸다: 템포, 박자표, 조성(설정돼 있으면), 대상 트랙의 프로그램 이름, 선택 범위 또는 커서 앞뒤 4마디의 클립을 계이름 텍스트로, 그리고 출력 형식 지시.
4. 응답을 스트리밍으로 받아 파싱하면서 고스트 클립이 차오른다. 완료되면 자동으로 한 번 들려준다(외부 신디로).
5. `Tab` 수락(실제 클립으로 확정, undo 한 단위), `Esc` 버림, `r` 같은 프롬프트로 재생성, `e` 프롬프트 수정 후 재생성, `Enter` 다시 듣기.

**생성 종류** (프롬프트에서 자동 판별하되 패널에서 고를 수도 있다)

| 종류 | 입력 | 결과 | 비고 |
| --- | --- | --- | --- |
| 새로 만들기 | 커서 위치, 역할(멜로디·코드·베이스·드럼·보컬), 마디 수(기본 8) | 빈 자리에 새 클립 | 역할은 트랙 프로그램으로 추정하되 패널에서 바꿀 수 있다. 보컬은 가사+멜로디를 함께 |
| 이어쓰기 | 커서 앞 클립 | 뒤에 이어지는 클립 | 동기·리듬·음역을 유지하도록 지시. 가사가 있으면 운율·주제도 이어 간다 |
| 변주 | 선택 범위 | 같은 길이의 새 클립(원본은 유지) | 받아들이면 원본을 대체할지 뒤에 둘지 묻는다 |
| 반주 만들기 | 선택 범위(멜로디) | 다른 트랙에 베이스·코드·드럼 클립 | 트랙이 없으면 새 트랙을 채널 자동 배정으로 만든다 |
| 화성 붙이기 | 선택 범위(멜로디) | 같은 트랙 또는 새 트랙에 코드 클립 | 조성이 있으면 그 안에서 |
| 가사에 멜로디 / 멜로디에 가사 | 가사만 있는 노트 열 또는 가사 없는 멜로디 | 음이 붙거나 가사가 붙은 클립 | 음절 수와 노트 수를 맞추도록 지시. 멜리스마 허용 |
| 필·전환 | 커서 앞뒤 클립 | 1–2마디의 필(드럼) 또는 전환구 | 마디 수 1–2로 고정 |
| 고치기 | 선택 범위 + 지시 | 수정된 클립 | "반음 올려" 같은 결정적 편집은 LLM 없이 처리하도록 먼저 분류 |

**규칙**

- AI는 절대 기존 노트를 묻지 않고 지우지 않는다. 결과는 항상 고스트로 먼저 오고, 수락 전까지 모델에 쓰지 않는다.
- 파싱에 실패한 응답은 원문을 패널에 보여 주고, 오류 메시지를 붙여 자동으로 한 번 재요청한다. 두 번째도 실패하면 사용자에게 맡긴다.
- 응답의 노트는 현재 길이 코드 그리드에 맞추고, 트랙 음역(설정)을 벗어나면 옥타브를 접는다.
- 보내는 내용은 패널의 "전송 내용 보기"로 언제든 확인할 수 있다. 사용자가 버튼을 누르기 전에는 아무것도 보내지 않는다.
- API 키는 macOS 키체인에 저장한다. 엔드포인트·모델 이름·최대 토큰·온도는 설정에서 바꾼다.
- 네트워크가 없으면 AI 패널은 열리되 생성 버튼이 비활성이고 이유를 보여 준다.

**어시스트: 다음 프레이즈 예측**

프롬프트를 쓰지 않아도, Step 모드에서 입력을 잠시 멈추면 AI가 **다음 1\~2마디를 고스트로 미리 보여 준다**. 코드 편집기의 자동 완성과 같은 흐름이다.

- 켜고 끄기는 **상단 트랜스포트의 `AI✦` 토글 버튼**(메뉴 AI > 어시스트, 팔레트 `assist on/off`). 기본 꺼짐. 켜져 있으면 마디 하나를 마치거나 입력이 1.5 s 멈출 때마다 커서 앞 8마디와 같은 시간대의 다른 트랙을 컨텍스트로 보내 다음 2마디를 받는다.
- 결과는 커서 뒤에 흐린 고스트 노트로 놓인다. 계속 치면 고스트는 조용히 사라지고, 멈추면 새 고스트가 온다. 고스트 위에 작은 `Tab ↵ 받아들이기` 힌트를 띄운다.
- `Tab`은 고스트가 보이는 동안 **다음 마디 끝까지 받아들이고** 커서를 그 뒤로 옮긴다(5.11의 "확정하고 다음으로"와 같은 뜻). 두 번 누르면 두 마디. 고스트가 없을 때의 `Tab`은 평소대로 다음 스텝이다. 마우스로는 고스트를 클릭해도 받아들인다.
- `Esc`는 고스트가 있으면 고스트만 지우고 Step 모드에 머문다. 한 번 더 누르면 Normal로 나간다.
- 요청은 입력을 가로막지 않는다. 백그라운드에서 받아 오고, 받는 동안 사용자가 커서를 옮기면 그 응답은 버린다. 요청 중에는 토글 버튼이 깜빡인다.
- 토큰 절약: 어시스트 요청은 응답 상한을 작게(기본 300 토큰) 두고, 같은 컨텍스트에 대한 응답은 캐시한다.
- 받아들인 고스트는 일반 노트가 되어 undo 한 단위로 묶인다. 어시스트가 받아들인 마디 수는 로그(AI-9)에 남긴다.

**모델과 엔드포인트**

기본 엔드포인트는 [OpenRouter](https://openrouter.ai)(OpenAI 호환, 키 하나로 여러 모델)다. 기본 모델은 둘을 두고 용도로 나눈다.

| 용도 | 기본 모델 (OpenRouter 슬러그) | 이유 |
| --- | --- | --- |
| 어시스트(다음 프레이즈, 자주·짧게) | `openai/gpt-5.6-luna` | 빠르고 싸다(입력 $0.20/M, 출력 $1.20/M). 300토큰 응답이 1.5 s 유휴마다 나가도 비용이 미미 |
| 생성(프롬프트, 8마디 멀티트랙) | `~anthropic/claude-haiku-latest` | 형식 준수와 음악적 일관성이 더 중요한 자리. 항상 최신 Haiku로 리다이렉트 |
| 로컬·오프라인 | 사용자 지정(Ollama 등) | 같은 설정 화면에서 베이스 URL만 바꾼다 |

두 자리 모두 설정에서 바꿀 수 있고, 프롬프트 실험실(아래)에서 모델별 결과를 비교한 뒤 고른다.

**프롬프트 설계**

LLM에 보내는 메시지는 네 층으로 조립하고, 각 층을 파일로 분리해 버전을 관리한다.

| 층 | 내용 | 누가 고치나 |
| --- | --- | --- |
| 시스템 | 역할, 출력 형식(`@track` 블록 + 계이름 텍스트), 문법 명세, 금지 사항(설명문 금지, 코드펜스 금지), 드럼 라벨 표 | 앱(번들). 사용자는 보기만 |
| 과제 템플릿 | 생성 종류별 지시(새로 만들기·이어쓰기·변주·반주·고치기·어시스트). 마디 수, 음역, 동기 유지 같은 제약을 변수로 받는다 | 앱이 기본 제공, **사용자가 복사해 고칠 수 있음** |
| 컨텍스트 | 템포·박자·조성·트랙 프로그램·앞뒤 클립·다른 트랙. 앱이 자동 조립 | 앱. 사용자는 포함 범위(마디 수, 트랙 수)만 설정 |
| 사용자 한 줄 | 프롬프트 패널에 쓴 문장 | 사용자 |

- 템플릿은 `~/Library/Application Support/KeyScore/prompts/`에 Markdown 파일로 두고 `{{bars}}` `{{key}}` `{{context}}` 같은 변수를 치환한다. 핫리로드.
- 과제 템플릿을 사용자가 고치면 원본 옆에 사본이 생기고, 패널에 "수정됨" 표시와 되돌리기 버튼이 뜬다. 앱 업데이트로 원본이 바뀌어도 사본은 유지된다.
- 어시스트 템플릿은 응답을 짧게 강제한다: 마디 수 2, 설명 금지, 컨텍스트의 마지막 노트에서 자연스럽게 이어질 것.
- 모든 템플릿은 few-shot 예시 한두 개를 품는다. 소형 모델은 명세보다 예시에 더 잘 따른다.

**프롬프트 실험실** (AI 패널의 "실험실" 탭, 메뉴 AI > 프롬프트 실험실)

템플릿·모델·컨텍스트를 바꿔 가며 결과를 나란히 보고 듣는 화면이다. 출시 전 튜닝용이지만 사용자에게도 연다.

- 고정 컨텍스트 세트(픽스처): 앱이 번들한 8곡(멜로디만, 멜로디+코드, 드럼만, 4트랙 등)과 사용자 프로젝트에서 따온 범위.
- 격자 실행: 픽스처 × 템플릿 버전 × 모델을 골라 한 번에 돌린다. 각 칸에 응답 원문, 파싱 결과(고스트 클립), 자동 점수, 지연, 토큰·비용.
- 자동 점수: 파싱 성공 여부, 요청 마디 수 일치, 음역 위반 노트 비율, 조성 밖 음 비율(조성이 있을 때), 리듬 밀도 편차, 앞 클립과의 음정 연속성(마지막 음과 첫 음 간격). 정답이 아니라 "깨졌는지"를 잡는 지표다.
- 듣기 비교: 칸을 골라 외부 신디로 재생, 좋은 쪽에 별표. 별표는 템플릿 버전·모델과 함께 기록된다.
- 결과는 `prompts/lab/<날짜>.json`으로 남아 템플릿을 고친 뒤 회귀 비교에 쓴다.

**프롬프트 템플릿 (앱 내장, 사용자 수정 가능)**

```text
너는 MIDI 시퀀서에 음악을 적는 작곡 보조다. 아래 형식으로만 답하라.
형식: 트랙마다 한 블록. 첫 줄 `@track <이름> ch<채널>`, 그 다음 MML.
MML 문법: o<옥타브> l<기본길이> c d e f g a b, +/- 반음, r 쉼표, 숫자 길이, . 점, & 타이.
마디 수: 8. 템포 120, 박자 4/4, 조성 C 장조.
기존 멜로디(트랙 Lead ch1): o5 l8 e d c d e e e4 d d d4 e g g4 ...
요청: 이 멜로디에 어울리는 베이스 8마디.
```

### 5.13 드럼 트랙 — GM 퍼커션 라벨

채널 10 트랙은 **드럼 트랙**이고, 음이름 대신 **GM 퍼커션 라벨**을 쓴다. Step 모드·계이름 텍스트·AI 응답·건반 뷰가 모두 같은 라벨을 공유한다. 라벨은 GM Level 1 퍼커션 키맵(노트 35–81)의 짧은 별칭이며, 전체 이름과 `n<번호>` 표기도 받는다.

| 라벨 | GM 이름 | 노트 | 건반 레이아웃 키 |
| --- | --- | --- | --- |
| `bd` | Bass Drum 1 | 36 | `A` |
| `sd` | Acoustic Snare | 38 | `S` |
| `rs` | Side Stick | 37 | `W` |
| `cp` | Hand Clap | 39 | `E` |
| `ch` | Closed Hi-Hat | 42 | `D` |
| `ph` | Pedal Hi-Hat | 44 | `R` |
| `oh` | Open Hi-Hat | 46 | `F` |
| `lt` | Low Tom | 45 | `G` |
| `mt` | Low-Mid Tom | 47 | `H` |
| `ht` | High Tom | 50 | `J` |
| `cr` | Crash Cymbal 1 | 49 | `T` |
| `rd` | Ride Cymbal 1 | 51 | `K` |
| `rb` | Ride Bell | 53 | `L` |
| `tb` | Tambourine | 54 | `Y` |
| `cb` | Cowbell | 56 | `U` |
| `sh` | Shaker (Maracas) | 70 | `O` |

- 드럼 트랙에서 Step 모드로 들어가면 건반 뷰가 위 라벨을 키 위에 보여 주고, `[` `]`는 옥타브 대신 **킷 페이지**(표에 없는 GM 노트 35–81을 두 페이지 더)를 넘긴다.
- 계이름 텍스트에서 드럼 트랙은 `@track Drums ch10` 뒤에 라벨을 쓴다. 동시 타격은 대괄호로 묶는다: `l16 [bd ch] ch [sd ch] ch [bd ch] ch [sd oh] r`. 대괄호 동시 표기는 멜로디 트랙의 화음(`[c e g]`)에도 같은 문법이다.
- AI 모드는 드럼 트랙에 대해 라벨 표와 대괄호 문법을 프롬프트에 함께 넣는다. 모델이 모르는 라벨을 내면 그 타격만 건너뛰고 패널에 표시한다.
- SMF 가져오기에서 채널 10 트랙은 자동으로 드럼 트랙이 되고, 표에 없는 노트 번호는 `n<번호>`로 보인다. 라벨 표는 설정에서 추가·수정할 수 있다(비GM 드럼 머신용).

### 5.14 계이름 텍스트 문법 명세 (KeyScore Text)

텍스트 가져오기·내보내기(IO-3), AI 요청·응답(5.12), 시스템 클립보드(7.5)가 공유하는 **하나의 문법**이다. MML의 공통 부분집합을 따르되, 다음 확장을 더한다: `@track` 헤더, `[ ]` 동시 표기, 드럼 라벨, `n` 셋잇단 접두. 키보드 입력 문법(5.6)과는 숫자의 뜻이 다르다 — 여기서는 MML 관례대로 **음 뒤의 숫자가 길이**이고 옥타브는 `o`·`<`·`>`로 적는다.

```text
// 주석은 // 뒤
@tempo 120          // 선택. 없으면 프로젝트 값
@time 4/4           // 선택
@key C major        // 선택. 'none' 가능

@track Lead ch1 prog0
o4 l8 c d e f g4 r4 | e d c4 c2 | [c e g]4 r4 c8&c8 d4 |

@track Bass ch2 prog33
o2 l4 c c g g | a a g2 |

@track Drums ch10
l16 [bd ch] ch [sd ch] ch [bd ch] ch [sd oh] r [bd ch] ch [sd ch] ch [bd ch] ch [sd oh] r |
n(ch ch ch) ch4 [bd cr]4 r8 sd8 sd8 |
```

**토큰**

| 토큰 | 뜻 | 비고 |
| --- | --- | --- |
| `@track <이름> ch<1–16> [prog<0–127>] [bank<n>]` | 트랙 블록 시작 | 이름이 같은 트랙이 있으면 거기에, 없으면 새로 만든다 |
| `@tempo` `@time` `@key` | 프로젝트 전역 값 | 가져올 때만 적용. 클립 단위 텍스트에서는 무시 |
| `c d e f g a b` | 음이름 | 뒤에 `+`/`#` 올림, `-` 내림(겹침 허용 `c++`) |
| `<숫자>` (음 뒤) | 길이, 분음표 단위 | `c4` 4분, `c16` 16분. 없으면 현재 `l` |
| `.` (길이 뒤) | 점음표 | `c4.` 점4분. `..` 겹점 |
| `&` | 타이(다음 같은 음과 이음) | `c8&c8` |
| `r` | 쉼표 | 길이 규칙 동일 |
| `o<0–9>` | 옥타브 절대 지정 | 스티키 |
| `<` `>` | 옥타브 ±1 | 스티키 |
| `l<숫자>` | 기본 길이 | 스티키. `l8.` 점음표 기본 |
| `[ ... ]` | 동시(화음·동시 타격) | 길이는 `]` 뒤에 한 번: `[c e g]4`. 안의 음은 길이 없이 |
| `n( ... )` | 셋잇단 묶음 | 괄호 안 3음이 그 길이의 2/3씩. `n(c d e)` 또는 `n(ch ch ch)` |
| `\|` | 마디선 | 선택. 파서는 검증에만 쓰고 틱 계산에는 안 씀. 마디 길이가 맞지 않으면 경고 |
| 드럼 라벨 `bd sd ch …` / `n<번호>` | 채널 10 트랙에서 음이름 대신 | 5.13절 표. 멜로디 트랙에서 쓰면 오류 |
| `v<0–127>` | 벨로시티 | 가져오기 때만 반영. v1의 내보내기·AI 응답은 생략 |
| `//` | 줄 끝까지 주석 | `#`는 주석이 아니다(음이름 뒤 올림표에만 쓴다) |

**규칙**

- 공백·줄바꿈은 토큰 구분일 뿐 뜻이 없다. 대소문자는 구분하지 않는다.
- 길이 숫자는 1·2·4·8·16·32·64와 점만 허용. 그 밖(`c3`, `c12`)은 오류.
- 한 `@track` 블록은 클립 하나가 된다. 커서 위치에서 시작하며, 길이는 내용으로 정해진다. 같은 텍스트 안에서 같은 이름의 `@track` 블록이 여러 번 나오면 모두 한 클립의 성부로 합친다(모두 같은 위치에서 시작하고, 클립 길이는 가장 긴 성부). 겹치는 노트를 적는 방법이며, 내보내기는 한 성부로 적을 수 없을 때만 성부를 나눈다.
- 가져오기는 **느슨하게**: 모르는 토큰(`t120`, `v15`, `@`, `q` 같은 다른 방언의 명령)은 경고하고 건너뛴다. 내보내기와 AI 응답은 이 표의 토큰만 쓴다.
- 내보내기는 틱 값을 가장 가까운 길이 표기로 적고, 그리드에 안 맞는 노트(퀀타이즈 안 된 녹음)는 `c8~+13`처럼 틱 오프셋 접미를 붙인다(`~` 뒤 ±틱). 길이도 맞지 않으면 `c4~+13:-20`처럼 `:` 뒤에 길이 보정(±틱)을 더한다(길이만이면 `c4~+0:-20`). 가져오기도 이 접미를 받는다. AI 응답에서는 금지.
- 파서는 `text` 크레이트에 두고, 속성 기반 테스트로 "내보내기 → 가져오기"가 원본과 같음을 검증한다.

### 5.15 가사

노트에 글자를 붙이는 기능이다. 보컬 멜로디를 쓸 때 음절을 음에 맞춰 두면 멜로디의 호흡이 보이고, AI가 가사와 멜로디를 함께 내거나 가사에 맞춰 멜로디를 고칠 수 있다. 모델이 JSON이라 노트에 필드 하나를 더하는 것으로 끝나므로 저장 비용은 거의 없다. 비용은 **입력 UI**(한글 IME가 들어오는 텍스트 모드)와 **멜리스마·분배 규칙**에 있다.

**모델**

- 노트에 선택 필드 `lyric: string`. 한 노트에 한 음절(또는 한 단어)이 기본. 비어 있으면 가사 없음.
- 멜리스마(한 음절을 여러 음에 걸침)는 이어지는 노트의 `lyric`을 `"-"`로 둔다(MusicXML·LilyPond의 extender와 같은 뜻). 표시에서는 밑줄로 잇는다.
- `.ksq`의 압축 배열에서는 다섯 번째 원소인 선택 속성 객체에 둔다: `[시작 델타, 길이, 음높이, 벨로시티, {"lyric": "사"}]`. 객체에는 `offset`(피치 오프셋)과 `lyric`이 이 순서로 들어가고, 기본값인 키는 쓰지 않는다. 선택 속성이 없는 노트는 네 원소 그대로라 기존 파일과 호환되고 크기도 늘지 않는다.
- 트랙 속성에 `lyric_lang`(ko·en·ja…)을 두어 분배 규칙과 AI 프롬프트에 쓴다.

**계이름 텍스트(5.14)**: 음 토큰 바로 뒤에 큰따옴표로 붙인다. `c8"사" d8"랑" e4"-" f4"해"`. 따옴표 안의 공백·기호는 그대로. 가져오기·내보내기·AI 응답 모두 같은 표기.

**입력 — 가사 모드**

- Normal에서 `w`(words)로 진입. 커서 위 노트부터 시작하고, 상태줄에 `LYRIC 3/16`과 현재 노트의 음이름을 보여 준다. 피아노롤은 가사 입력 중인 노트를 강조한다.
- 이 모드만은 **문자 입력 모드**다: KM-7의 물리 키 매칭을 끄고 macOS IME(한글·일본어)를 그대로 받는다. 글자를 치면 현재 노트에 붙고, `Space`·`Tab`은 다음 노트, `Shift+Tab`은 이전 노트, `-`는 멜리스마 표시 후 다음 노트, `Backspace`는 현재 노트의 가사를 지우고 비어 있으면 이전 노트로, `Esc`는 Normal로.
- **한 줄 붙여넣기 분배**: 노트를 선택하고 가사 모드에서 `Cmd+V`로 문장을 붙이면 음절 단위로 노트에 차례로 나눈다. 한국어·일본어는 글자 단위(공백 무시), 영어는 하이픈·공백 단위(`lov-ing you` → `lov` `ing` `you`), 하이픈이 없는 영어 단어는 한 노트에 통째로. 노트가 남으면 비워 두고, 음절이 남으면 상태줄에 경고.
- 마우스: 노트 더블클릭 대신 가사 모드에서 노트를 클릭하면 그 노트로 커서 이동.

**표시**: 피아노롤에서 노트 막대 아래(또는 안)에 작은 글자. 줌이 작으면 숨기고, 멜리스마는 밑줄로 잇는다. 배치 뷰의 클립 블록에는 첫 소절 가사를 제목처럼 흐리게 보인다(가사가 있는 클립만).

**입출력**

- SMF: 노트마다 Lyric 메타 이벤트(0x05)를 같은 틱에 쓴다. 가져오기도 같은 규칙으로 노트에 붙인다(가장 가까운 노트 온). 표준이라 다른 DAW·악보 프로그램과 왕복된다.
- 외부 신디로의 실시간 송신에는 가사가 없다(MIDI 1.0에 가사 메시지가 없다). 보컬 신디(Synthesizer V, Vocaloid)는 각자의 파일 포맷으로 가사를 받으므로, 그쪽 내보내기(UST·VSQX·SVP)는 이후 고려.

**AI**: 프롬프트 패널의 역할에 "보컬(가사 포함)"을 더한다. 컨텍스트에 기존 가사가 들어가고, 응답은 `c8"사"` 표기로 가사와 음을 함께 낸다. 어시스트도 가사가 있는 트랙에서는 다음 소절의 가사를 함께 제안한다. 자동 점수에 "노트당 음절 수 ≤ 1" 검사를 더한다.

### 7.4 마우스 편집

키보드가 1급이지만, 피아노롤 뷰와 배치 뷰에서 **마우스로 노트·클립을 골라 한꺼번에 옮기고 늘이는 조작**은 키보드 조작과 같은 수준으로 지원한다. 마우스 조작은 5.7·5.10의 키 조작과 같은 Action을 호출하므로 되돌리기·카운트·선택 상태가 두 입력 사이에서 공유된다.

**선택**

| 조작 | 피아노롤 뷰 (노트) | 배치 뷰 (클립) |
| --- | --- | --- |
| 클릭 | 그 노트만 선택 | 그 클립만 선택 |
| `Cmd+클릭` | 선택에 추가/제거 | 선택에 추가/제거 |
| `Shift+클릭` | 마지막 선택부터 시간 범위로 확장 | 같은 트랙에서 범위 확장 |
| 빈 곳에서 드래그 | 사각형(러버밴드) 안의 노트 선택. 시간×음높이 | 사각형 안의 클립 선택. 트랙×시간 |
| `Cmd+드래그` | 사각형 안을 선택에 추가 | 같음 |
| 더블클릭 (빈 곳) | 현재 길이 코드의 노트 생성 | 마디 단위 빈 클립 생성 |
| 더블클릭 (노트/클립) | 노트 삭제 | 클립 안으로 들어감 |

마우스 선택은 `v` 비주얼 모드와 같은 선택 상태를 만든다. 마우스로 고른 뒤 `Alt+k`로 올리거나, `v`로 고른 뒤 마우스로 끌어도 된다.

**이동·조절** (선택된 것 전부에 한꺼번에 적용)

| 조작 | 노트 | 클립 |
| --- | --- | --- |
| 본체 드래그 | 시간·음높이 이동. 그리드에 스냅(`Cmd`를 누르면 스냅 해제) | 시간·트랙 이동. 마디 스냅, 겹치면 뒤로 밀기 |
| 오른쪽 끝 드래그 | 끝 조절(길이) | 끝 조절, 비파괴 트림 |
| 왼쪽 끝 드래그 | 시작점 조절(끝 고정) | 시작점 트림 |
| `Alt+드래그` | 복제해서 이동 | 복제해서 이동 |
| `Shift+드래그` | 한 축으로만 이동(시간 또는 음높이) | 한 축으로만(시간 또는 트랙) |
| 드래그 중 `Esc` | 취소, 원위치 | 취소 |
| 휠 / `Shift+휠` | 세로 / 가로 스크롤 | 같음 |
| `Cmd+휠`, 핀치 | 가로 줌 | 가로 줌 |

**요구사항**

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| MS-1 | 위 선택·이동·조절 표 전부. 러버밴드와 드래그 중에는 결과를 미리 보여 주고(고스트), 놓는 순간 한 번의 undo 단위로 적용 | M |
| MS-2 | 다중 선택 드래그는 상대 위치를 유지한다. 길이 조절은 선택 전부의 끝을 같은 양만큼 움직인다 | M |
| MS-3 | 스냅: 노트는 현재 길이 코드의 그리드, 클립은 마디. `Cmd` 누른 채로 자유 이동. 설정에서 스냅 단위 변경 | M |
| MS-4 | 드래그 중 노트는 외부 신디로 미리듣기 송신(음높이가 바뀔 때마다 한 번) | S |
| MS-5 | 마우스 커서 위치가 키보드 커서와 다를 때, 키 조작은 키보드 커서 기준이고 마우스 조작은 마우스 위치 기준이다. 클릭하면 키보드 커서가 그 자리로 온다 | M |
| MS-6 | 끝 드래그 영역은 노트·클립 가장자리 6 px, 작은 노트에서는 전체 폭의 1/3로 줄어든다 | M |
| MS-7 | 트랙패드 제스처: 두 손가락 스크롤, 핀치 줌. 드래그는 탭-드래그 설정을 따른다 | S |

### 7.5 macOS 표준 단축키

macOS 사용자가 어느 앱에서나 기대하는 `Cmd` 단축키는 **모든 키맵 프리셋에서 항상 같은 뜻으로 동작**한다. vim 키(`y` `d` `p` `u`)와 나란히 존재하며 같은 Action을 부른다. `Cmd`는 5.7의 수식키 체계(`Ctrl`/`Alt`/`Shift`)에서 비워 두었으므로 충돌이 없다.

| 단축키 | 동작 | vim 대응 | 비고 |
| --- | --- | --- | --- |
| `Cmd+Z` | 되돌리기 | `u` |  |
| `Cmd+Shift+Z` | 다시 실행 | `U`, `Ctrl+r` |  |
| `Cmd+X` | 잘라내기 | `x`(선택 시) | 노트·클립·레인 포인트 모두 |
| `Cmd+C` | 복사 | `y` |  |
| `Cmd+V` | 붙여넣기 | `p` | 커서 위치에, 클립은 겹치면 뒤로 밀기 |
| `Cmd+D` | 복제(바로 뒤에 붙여넣기) | `yyp`류 | 선택의 길이만큼 뒤에 |
| `Cmd+A` | 전체 선택 | `ggVG` | 피아노롤은 클립 안 노트 전부, 배치 뷰는 클립 전부 |
| `Cmd+N` / `Cmd+O` / `Cmd+S` / `Cmd+Shift+S` | 새 프로젝트 / 열기 / 저장 / 다른 이름으로 | `:new` `:e` `:w` `:w name` |  |
| `Cmd+W` / `Cmd+Q` | 창 닫기 / 종료 | `:q` | 저장 안 된 변경은 macOS 표준 시트로 묻기 |
| `Cmd+,` | 설정 | `:set` | 키맵 편집 화면 포함 |
| `Cmd+Shift+P` | 명령 팔레트 | `:` | `Ctrl+Shift+P`도 유지 |
| `Cmd+F` | 검색 | `/` |  |
| `Cmd+=` / `Cmd+-` / `Cmd+0` | 줌 인 / 줌 아웃 / 줌 초기화 | `zl` `zh` |  |
| `Cmd+Return` | 재생/정지 | `Ctrl+Space` | `Space` 단독은 Step 모드의 쉼표라 쓰지 않는다 |
| `Cmd+.` | 패닉(All Notes Off) | `Ctrl+.` | macOS의 "중단" 관례 |

**클립보드 규칙**

- 복사한 노트·클립은 앱 내부 클립보드에 구조 그대로 두고, 시스템 클립보드에는 같은 내용을 SMF Type 0 바이트와 계이름 텍스트(MML)로 함께 올린다. 다른 앱에 붙여 넣으면 텍스트가, KeyScore 안에서는 구조가 쓰인다.
- 붙여넣기 위치는 키보드 커서. 노트는 클립 경계를 넘으면 클립을 늘리고, 클립은 겹치면 뒤로 민다.
- 시스템 클립보드에 SMF나 MML 텍스트가 있으면 `Cmd+V`로 가져온다(IO-2·IO-3과 같은 변환).

**요구사항**

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| KM-12 | 위 `Cmd` 단축키는 세 프리셋 공통이며 프리셋이 덮어쓰지 않는다. 사용자 오버라이드로는 바꿀 수 있되 경고를 띄운다 | M |
| KM-13 | 메뉴바(파일·편집·보기·트랙·재생·도움말)에 같은 단축키를 표시한다. 메뉴 항목은 Action과 1:1 | M |
| KM-14 | `Cmd+Z`/`Cmd+Shift+Z`는 텍스트 입력 중(명령줄·이름 편집)에는 그 텍스트 필드의 undo를 따른다 | M |
| KM-15 | 시스템 클립보드 왕복(SMF·MML 텍스트) | S |

| 되돌리기·다시 실행 | 메뉴 편집 | `Cmd+Z`, `Cmd+Shift+Z` |  |

메뉴바 구성: **파일**(새로 만들기·열기·저장·다른 이름·SMF 가져오기·내보내기·계이름 텍스트 가져오기·내보내기·최근 파일) · **편집**(되돌리기·다시 실행·잘라내기·복사·붙여넣기·복제·반복·전체 선택·분할·합치기·퀀타이즈·레가토) · **보기**(배치 뷰·컨트롤러 레인·트랙 인스펙터·건반 뷰·줌·테마) · **트랙**(새 트랙·삭제·뮤트·솔로·위로·아래로·포트·채널) · **재생**(재생·정지·커서부터·루프·녹음·메트로놈·패닉) · **AI**(생성·어시스트·프롬프트 실험실·템플릿 폴더) · **도움말**(키맵 보기·온보딩 다시 보기·문서). 모든 메뉴 항목은 Action과 1:1이며 팔레트에서 같은 이름으로 검색된다.

### 7.7 온보딩

첫 실행에서 **10분 안에 소리가 나야 한다**. 세 단계이며 각 단계는 건너뛸 수 있고 도움말 메뉴에서 다시 열 수 있다.

1. **소리 연결**: 가상 포트 이름(`KeyScore Out`)을 크게 보여 주고, 추천 신디(Surge XT, Vital, Dexed) 설치 링크와 "그 앱에서 MIDI 입력으로 이 포트를 고르세요" 안내. "테스트 노트 보내기" 버튼을 누르면 들리는지 묻고, 들리면 다음으로. 안 들리면 흔한 원인(신디가 입력을 안 골랐음, 채널 불일치) 체크리스트.
2. **Step 입력 4마디**: 레이턴시 보정 마법사(10번 탭) 뒤, 건반형 레이아웃 표시 상태에서 `Enter`로 Step에 들어가 `A S D F`로 4마디를 치게 한다. 길이 코드 한 번(`5`), `Shift+음` 한 번, `Tab` 한 번을 각각 써 보게 한다. 계이름형으로 바꿀 수 있다는 안내 한 줄.
3. **미리 적기 + Sequence 녹음**: 방금 찍은 4마디를 두고 `Cmd+R`로 녹음에 들어가 `Space`만 박자에 맞춰 누르게 한다. 판정 색을 보여 주고, 자동 퀀타이즈된 결과를 들려 준 뒤 `Cmd+Z`로 테이크를 되돌려 보게 한다.

끝나면 "다음 단계" 카드로 배치 뷰(`v`)·컨트롤러 레인(`c`)·AI 패널(`a`, OpenRouter 키 설정 링크)을 소개한다. 온보딩 중 만든 프로젝트는 자동 저장본으로만 남고, 사용자가 `Cmd+S`를 누를 때 파일이 된다.

타이밍 정밀도가 이 제품의 품질을 결정한다. 수치는 모두 측정 가능한 형태로 두고 CI에서 자동 검증한다.

### 8.1 타이밍·지연

| ID | 항목 | 목표 | 측정 방법 |
| --- | --- | --- | --- |
| NF-1 | 키 입력 → MIDI 송신 | ≤ 3 ms (p99) | 가상 포트 루프백으로 OS 타임스탬프 비교 |
| NF-2 | 가상 포트 → 수신 앱 도착 | ≤ 1 ms (p99) | 같은 컴퓨터의 수신 테스트 앱에서 OS 타임스탬프 비교. 그 뒤의 오디오 지연은 외부 신디 몫 |
| NF-3 | 재생 시 MIDI 이벤트 지터 | ≤ 0.5 ms (p99) | 1시간 재생 중 송신 간격 표준편차 |
| NF-4 | 템포 드리프트 | 1시간 재생 후 ≤ 1 ms | 모노토닉 클록 vs 누적 틱 시간 비교 |

| ID | 항목 | 목표 |
| --- | --- | --- |
| NF-6 | 콜드 스타트(가상 포트 등록 포함) | ≤ 0.5 s |

### 8.3 플랫폼: macOS 전용

| 항목 | 요구 |
| --- | --- |
| OS | macOS 14 Sonoma 이상. Apple Silicon 네이티브, Intel은 가능하면 유니버설 바이너리 |
| MIDI API | CoreMIDI. v1은 MIDI 1.0 프로토콜 가상 소스와 `MIDIPacketList`/`MIDIEventList` 예약 송신. UMP(MIDI 2.0)는 같은 API의 프로토콜 옵션이므로 이후 버전에서 코드 변경 범위가 작다 |
| 가상 포트 | CoreMIDI 가상 소스. 별도 드라이버 불필요 |
| 키 이벤트 타임스탬프 | `NSEvent.timestamp` (시스템 업타임 기준). GPUI가 노출하는지 확인 필요(12절) |
| 배포 | 개인 Developer ID로 서명한 .app을 GitHub Releases·Homebrew cask로 직접 배포. 개발 중에는 공증하지 않고 Gatekeeper 경고를 직접 처리하며, 공증은 배포 전 단계에서 재검토. Mac App Store와 판매 모델은 v2.0 이후 고려. 샌드박스 비적용 |

macOS 전용으로 두면 CoreMIDI 하나로 가상 포트·예약 송신이 모두 해결되고, 플랫폼 추상화 트레이트가 없어진다. v1은 MIDI 1.0 프로토콜로 소스를 만들어 모든 수신 앱과 호환되며, 이후 MIDI 2.0을 붙일 때는 소스 프로토콜과 패킷 인코딩만 바꾼다.

### 8.4 안정성·기타

- MIDI 스케줄러 스레드에서는 할당·락·시스템 콜(MIDI 송신 API 제외) 금지. 위반은 디버그 빌드에서 `assert_no_alloc`류 검사로 잡는다.
- 가상 포트는 앱이 비정상 종료해도 OS에 남지 않아야 한다(등록 해제는 OS가 프로세스 종료 시 처리하지만, 플랫폼별로 확인).
- 크래시 시 `~/Library/Application Support/KeyScore/autosave/` 복구본에서 복구, 이전 프로젝트 파일은 덮어쓰지 않는다.
- 라이선스: 앱 소스는 BSD-3-Clause. 의존성은 BSD와 호환되는 허용적 라이선스(Apache-2.0, MIT, BSD, Zlib, ISC, Unicode-3.0, bzip2-1.0.6)와 MPL-2.0만 쓴다. MPL-2.0 crate는 파일 단위 copyleft라 수정 없이 쓴다. gpui-kit·Ely(Apache-2.0)는 NOTICE 고지를 함께 배포한다.
- 국제화: UI 문자열은 Fluent(.ftl)로 외부화(ko, en). 시스템 언어가 한국어면 한국어, 아니면 영어.
- 텔레메트리 없음. 앱은 AI 요청 외에 어떤 데이터도 보내지 않는다. 크래시는 macOS 리포트를 사용자가 GitHub 이슈에 붙이는 안내만 둔다.
- 업데이트: 앱 내 자동 업데이트 없음. GitHub Releases·Homebrew cask로 배포하고 도움말 메뉴에 "새 버전 확인" 링크.
- CI: GitHub Actions macOS 러너에서 빌드·테스트·서명 빌드. 1시간 재생 지터 테스트(NF-3, NF-4)는 야간 작업.

## 9. 기술 아키텍처

두 스레드(UI·MIDI 스케줄러)가 락 없는 큐로만 통신하고, 시퀀서 모델은 출력 계층에 의존하지 않는 순수 데이터다. 오디오 스레드는 없다.

UI는 모델을 바꾸고, 스케줄러는 모델의 스냅샷을 읽어 시각이 붙은 MIDI 메시지를 출력 계층으로 흘려보낸다. 출력 계층은 앱이 등록한 가상 포트와 OS의 다른 포트에 같은 메시지를 쓴다. 가상 포트를 듣고 있는 스탠드얼론 신디가 소리를 낸다. 파일 I/O는 모델과만 대화한다.

### 9.3 Sequence 모드의 타임스탬프 경로

키 이벤트는 GPUI 메인 스레드에서 들어오므로 프레임 지연(최대 16.7 ms)이 섞인다. 이를 피하기 위해:

1. `NSEvent.timestamp`(시스템 업타임 기준 초)를 쓴다. GPUI가 이 값을 Action까지 전달하는지 확인하고, 안 하면 GPUI의 macOS 플랫폼 계층에 패치 또는 자체 이벤트 모니터(`NSEvent.addLocalMonitorForEvents`)를 붙인다.
2. 둘 다 안 되면 수신 즉시 `mach_absolute_time()`을 찍고, 사용자 보정 오프셋을 뺀다.
3. 스케줄러의 재생 시각 기준(같은 mach 클록)으로 변환해 틱으로 환산한다. CoreMIDI 타임스탬프도 같은 클록이므로 변환이 없다.

GPUI가 플랫폼 키 이벤트의 원본 타임스탬프를 노출하는지는 **확인 필요** 항목이다(12절).

### 9.4 UI 컴포넌트: 가져다 쓰는 것과 직접 그리는 것

화면의 틀과 보조 UI는 [gpui-kit](https://gpui-kit.com/component/)에서 가져오고, 시간축 위에 노트·클립·곡선을 그리는 네 화면만 직접 만든다. 두 라이브러리 모두 GPUI(Zed)와 같은 Apache-2.0이라 라이선스 문제가 없다.

| 화면 요소 (7.1절) | gpui-kit 컴포넌트 | 비고 |
| --- | --- | --- |
| 창 틀·패널 분할 | `Root`, `Dock`, `Resizable` | 트랙 목록·메인·레인·건반 뷰의 접기·크기 조절 |
| 상단 트랜스포트 | `Toolbar`, `Button`, `NumberInput`(템포), `Badge`(포트 연결 상태) |  |
| 하단 상태줄 | `StatusBar` | 모드·길이·옥타브·포트, 오른쪽에 메시지 |
| 명령 팔레트 `:` / `Ctrl+Shift+p` | `Command` | Action 이름 검색, 단축키 표시 |
| 키맵 편집 화면 (7.3절) | `Settings`, `DataTable`, `Kbd`, `Input` | press-to-bind 캡처는 자체 포커스 처리 |
| `?` 키맵 오버레이 | `Sheet` 또는 `Popover` + `Kbd` |  |
| 트랙 목록 | `List` 또는 `VirtualList`, `Menu`(우클릭) | 포트·채널 상시 표시 |
| 포트·채널·프로그램 선택 | `Select`, `Combobox` | GM 이름 검색 |
| 대화상자·알림 | `Dialog`, `AlertDialog`, `Notification` | 채널 충돌 경고, 포트 소멸 알림 |
| 테마 | `Theme` | 다크·라이트, 사용자 테마 JSON(UI-7)과 연결 |
| **피아노롤 뷰** | 없음 → 자체 Element | 노트 10,000개 인스턴싱, 커서·선택·재생 헤드 |
| **배치 뷰** | 없음 → 자체 Element | 트랙×시간 격자, 클립 블록 |
| **컨트롤러 레인** | 없음 → 자체 Element | 벨로시티 막대·CC 곡선, 마우스 드래그 그리기 |
| **건반 뷰·Sequence 레인** | 없음 → 자체 Element | 키 라벨 오버레이, 흐르는 박자 그리드 |

[Ely](https://ely-gpui.zacharyzhang.com/components/)는 gpui-kit과 같은 GPUI 스냅샷 위에서 함께 쓸 수 있으므로, 팔레트와 다크·라이트 대비를 Ely 기준으로 잡고 부족한 컴포넌트를 보충하는 용도로 둔다. 두 라이브러리 모두 `gpui-pre-*` 스냅샷에 묶여 있어, 자체 Element는 그 스냅샷의 `Element` API로 작성하고 GPUI 본가 버전을 따로 추적하지 않는다.

### 9.5 프로젝트 파일 포맷 — 텍스트 vs 바이너리 비교

노트 한 개는 (시작 틱, 길이, 음높이, 벨로시티) 네 값이다. 아래는 무작위 노트로 측정한 크기이며, 실제 곡은 반복이 많아 압축률이 더 좋다. 기준 규모: 5분짜리 팝 곡의 SMF는 보통 50–200 KB, 노트 5,000–20,000개. 100,000개는 교향곡 전곡 수준이다.

| 인코딩 | 노트당 | 10,000개 raw | 100,000개 raw | 100,000개 gzip |
| --- | --- | --- | --- | --- |
| JSON 객체, 들여쓰기 | 67 B | 648 KB | 6.6 MB | 647 KB |
| JSON 객체, 압축 표기 | 37 B | 355 KB | 3.6 MB | 609 KB |
| JSON 배열 `[t,d,p,v]` | 21 B | 199 KB | 2.1 MB | 564 KB |
| JSON 배열 + 시작 틱 델타 | 16 B | 158 KB | 1.6 MB | 281 KB |
| MessagePack 배열 | 10 B | 101 KB | 1.0 MB | 514 KB |
| 고정 바이너리 구조체 | 11 B | 107 KB | 1.1 MB | 510 KB |

**바이너리의 장점이 실제로 있는 곳**

- 크기: 압축 표기 JSON 대비 1.5–2배 작다. 그러나 gzip을 씌우면 델타 JSON(2.8 B/노트)이 raw 바이너리(10 B/노트)보다 작다. 디스크·전송 크기는 바이너리의 논거가 되지 못한다.
- 파싱 속도: 10만 노트 기준 serde\_json 수십 ms, 고정 구조체 수 ms. 둘 다 파일 열기 체감 아래다. 1만 노트면 차이가 1 ms 단위.
- 부분 로드·메모리 매핑: 수 GB 파일을 다룰 때만 의미가 있다. MIDI 프로젝트는 그 규모에 이르지 않는다.
- 정밀 실수값 보존: 모델이 정수(틱·7/16비트 값)만 쓰므로 해당 없음.

**바이너리의 비용**

- git diff·머지·리뷰가 불가. 사용자가 깨진 파일을 직접 열어 고칠 수 없다.
- 스키마 진화: 고정 구조체(bincode류)는 필드 하나만 추가해도 옛 파일이 깨져 버전마다 마이그레이션 코드가 필요하다. MessagePack·CBOR은 자기 기술적이라 이 문제는 없지만 diff 불가는 같다.
- 외부 도구·LLM·스크립트가 바로 읽지 못한다.

**선례**: Reaper(`.rpp`)는 평문 텍스트, Ableton(`.als`)·MuseScore(`.mscz`)·Renoise는 gzip/zip으로 싼 XML, Logic·Bitwig는 바이너리 패키지. 텍스트+압축이 주류다.

**제안**: 내용은 JSON, 노트는 `[시작 델타, 길이, 음높이, 벨로시티]` 배열(선택 속성이 있으면 다섯 번째 원소로 `{"offset": …, "lyric": …}` 객체), CC 포인트는 `[틱 델타, 값]` 배열로 압축 표기한다. 파일은 기본 **평문**(`.ksq`, git 친화)이고 설정에서 gzip 저장(`.ksqz`, 1/5 크기)을 켤 수 있다. 1만 노트 곡이 160 KB, 10만 노트가 1.6 MB(gzip 280 KB)라 바이너리로 얻을 것이 없고, 잃을 것(diff·복구·도구 호환)은 크다. 파일 헤더에 `format_version`을 두고 하위 호환 규칙(모르는 키는 보존, 없는 키는 기본값)을 둔다.

### 9.6 저장소 구조

Cargo 워크스페이스 다섯 크레이트. 의존 방향은 아래에서 위로만 흐르고, `core`와 `text`는 GPUI·CoreMIDI·네트워크에 의존하지 않는다.

| 크레이트 | 내용 | 의존 |
| --- | --- | --- |
| `keyscore-core` | 모델(프로젝트·트랙·클립·노트·CC 포인트), 템포 맵, undo, 퀀타이즈, `.ksq` 직렬화 | serde, serde\_json |
| `keyscore-text` | 계이름 텍스트 파서·내보내기(5.14절), 드럼 라벨 표 | core |
| `keyscore-midi` | CoreMIDI 가상 포트·포트 열거, 스케줄러 스레드, MIDI 1.0 인코딩, SMF 입출력 | core, coremidi, midly, rtrb |
| `keyscore-ai` | OpenRouter 클라이언트, 템플릿 로더·변수 치환, 컨텍스트 조립, 실험실 평가(자동 점수) | core, text, reqwest |
| `keyscore-app` | GPUI UI, 키맵, 모드 FSM, 온보딩, 설정 | 전부 + gpui-kit |

- `core`와 `text`는 순수 Rust라 CLI 도구(`ksq2mid`, `mid2ksq`, 텍스트 변환)와 속성 기반 테스트를 UI 없이 돌린다.
- 통합 테스트는 `midi`에서 가상 포트 루프백(송신 → 수신 테스트 앱)으로 NF-1·NF-3를 측정한다.
- 프롬프트 템플릿·픽스처·번역 파일은 `app/assets/`에 두고 빌드에 포함한다.

## 12. 미결 사항과 리스크

가장 큰 기술 리스크는 **GPUI가 키 이벤트의 원본 타임스탬프를 넘겨주는지**와 **가상 포트에 신디가 붙었는지 알 수 있는지**다. 둘 다 M0 착수 전에 작은 프로토타입으로 확인한다.

### 12.1 확인이 필요한 질문

- [ ] GPUI가 `NSEvent.timestamp`를 Action까지 전달하는가? 없으면 Sequence 모드 정밀도가 프레임 지연에 묶인다(9.3절)
- [ ] GPUI(gpui-kit이 고정한 스냅샷)에서 커스텀 Element로 GPU 인스턴싱(노트 10,000개)을 할 수 있는가, 아니면 자체 Metal/`wgpu` 패스를 끼워 넣어야 하는가
- [ ] coremidi 크레이트로 가상 소스 생성과 타임스탬프 예약 송신이 되는가, 아니면 core-midi-sys로 직접 호출해야 하는가
- [ ] 가상 포트에 리스너가 붙었는지 CoreMIDI로 확인할 수 있는가(PRE-2). 없으면 테스트 노트 안내만으로 충분한가
- [ ] 소형 모델이 8마디 멀티트랙 텍스트를 얼마나 안정적으로 내는가 — 실험실(AI-16)로 `gpt-5.6-luna`·`claude-haiku-latest`·로컬 모델 1종을 먼저 비교
- [ ] 어시스트 응답 지연의 체감 상한 2 s가 실제로 적절한가 — 측정 후 조정

### 12.2 리스크

| 리스크 | 영향 | 완화 |
| --- | --- | --- |
| GPUI API 변동 | 업그레이드마다 UI 코드 수정 | UI 계층을 얇게 유지, 모델·스케줄러는 GPUI 의존 없음. 버전 고정 후 분기별 업그레이드 |
| 신디 연결 전엔 무음 | 첫 실행에서 "소리가 안 난다"로 이탈 | 온보딩에서 가상 포트 이름과 연결 절차 안내(PRE-2), 무료 스탠드얼론 신디 추천 목록, 시각 메트로놈과 `:test` |
| 채널 충돌 | 두 트랙이 같은 포트·채널에 다른 프로그램을 보내 음색이 뒤섞임 | SEQ-8 경고, 새 트랙 자동 채널 배정, 트랙 목록에 포트·채널 상시 표시 |
| 키 이벤트 타임스탬프 부재 | Sequence 모드 정확도 저하 | 보정 마법사로 평균 오프셋 흡수, 퀀타이즈 기본 켬. 필요 시 NSEvent 모니터 추가 |
| 모달 편집의 학습 곡선 | 입문자 이탈 | `?` 키맵 오버레이, 첫 실행 튜토리얼, 건반 레이아웃 기본값 |
| 클립 모델의 편집 복잡도 | 클립 경계를 넘는 선택·이동·붙여넣기에서 엣지 케이스 다수 | 노트 편집은 클립 안으로 제한(5.3), 경계를 넘는 조작은 배치 뷰에서만. 속성 기반 테스트로 불변식(겹침 없음, 노트는 클립 안) 검증 |
| AI 응답 품질·형식 깨짐 | 파싱 실패, 음악적으로 쓸모없는 결과로 기능 신뢰 상실 | 계이름 텍스트(단순 문법)로 제한, 자동 재요청 1회, 고스트로만 제시해 모델을 더럽히지 않음, 프롬프트 템플릿을 사용자가 고칠 수 있게 |
| AI 외부 의존 | API 키·네트워크·비용·프라이버시 | 전송 내용 보기, 키체인 저장, 로컬 서버(Ollama) 지원, AI 없이도 모든 기능 동작 |
| 실시간 스레드 규율 위반 | 재생 중 글리치 | 디버그 빌드 할당 검출, 스레드별 린트, 1시간 재생 CI 테스트(NF-3, NF-4) |

## 13. 벤치마크 — MIDI Agent

[MIDI Agent](https://www.midiagent.com/features)는 텍스트 프롬프트로 MIDI를 만드는 VST3/AU/AAX 플러그인·스탠드얼론 앱이다(플러그인 $49 평생, 관리형 Pro $20/월 500회). AI 모드의 직접 비교 대상이며, 아래는 2026-09 기준 기능 페이지에서 확인한 내용이다.

**MIDI Agent가 하는 것**

| 영역 | MIDI Agent | KeyScore v1 |
| --- | --- | --- |
| 생성 종류 | 코드·멜로디·베이스·드럼, 기존 MIDI 확장·변주·필·전환, 스마트 하모나이즈 | 같은 범위(5.12 표). 필·전환·화성 붙이기를 이번에 추가 |
| 프롬프트 입력 | 자유 문장 + **구조화 파라미터**(키, 스케일, 마디 수, 노트 길이, 장르) | 자유 문장만이었음 → 구조화 필드 추가(아래 AI-20) |
| 대화형 후속 지시 | 한 대화 안에서 "밀도 줄여", "리듬 바꿔" 같은 후속 요청, 새 아이디어면 새 대화 | 재생성·프롬프트 수정만 → 후속 지시 추가(AI-21) |
| 사용자 맞춤 | 설정의 custom instructions(취향 서술), 참조 MIDI 파일 첨부 | 템플릿 수정만 → 취향 지시·참조 클립 추가(AI-22, AI-23) |
| 모델 접근 | ChatGPT 계정, 각사 API 키, OpenRouter, Ollama·LM Studio, 관리형 Pro(Lyria·PozaLabs 등) | OpenRouter + 로컬 서버. 관리형 접근 없음 |
| 오디오→MIDI 전사 | 있음 | 없음(오디오 경로 없음, 계획 없음) |
| 결과 전달 | MIDI 파일 저장 또는 DAW로 드래그 → DAW에서 편집 | 커서 위치에 고스트 클립 → `Tab` 수락, 제자리 편집 |
| 작업 중 보조 | 없음(요청-응답만) | 어시스트: 입력 중 다음 프레이즈 자동 제안 |
| 컨텍스트 | 사용자가 첨부한 MIDI만 | 앞뒤 클립·다른 트랙·조성·템포를 앱이 자동 조립 |
| 출력 형식 | (비공개) MIDI 파일 생성 | 계이름 텍스트 → 파서 → 클립. 실험실에서 모델·템플릿 비교 |

**KeyScore가 다른 점**: MIDI Agent는 "생성기 → 파일 → DAW"의 세 단계이고, KeyScore는 생성 결과가 편집 중인 자리에 고스트로 바로 놓이며 입력 중 어시스트가 끼어든다. 컨텍스트도 사용자가 첨부하는 대신 앱이 커서 주변에서 자동으로 뽑는다. 이 둘이 AI 모드의 핵심 차별점이고, 모델 다양성·오디오 전사·관리형 요금제는 따라가지 않는다.

**MIDI Agent에서 가져오는 것** (6.8절 요구사항에 추가)

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| AI-20 | 프롬프트 패널에 구조화 필드: 역할(멜로디·코드·베이스·드럼), 마디 수, 음역(옥타브 범위), 밀도(성김/보통/촘촘), 분위기·장르 자유어. 필드 값은 템플릿 변수로 들어가고 자유 문장은 그 뒤에 붙는다. 비워 두면 커서·트랙에서 추정 | M |
| AI-21 | 후속 지시: 고스트가 떠 있는 동안 "더 성기게", "리듬만 바꿔" 같은 한 줄을 추가로 보내면 직전 요청·응답을 대화 컨텍스트로 유지한 채 다시 생성한다. 재생성 이력은 `Shift+Tab`으로 되돌아볼 수 있다(5.11). 새 요청은 대화를 비운다 | M |
| AI-22 | 취향 지시(custom instructions): 설정 > AI의 자유 텍스트 한 칸. 모든 요청의 시스템 층 뒤에 붙는다. 예: "항상 4마디 단위로 프레이즈를 끊고, 7th 코드를 즐겨 써라" | S |
| AI-23 | 참조 클립: 프롬프트 패널에서 프로젝트의 다른 클립을 "이 느낌으로"로 첨부하면 계이름 텍스트로 컨텍스트에 들어간다(최대 2개, 토큰 상한 안에서) | S |
| AI-24 | 실험실 픽스처에 MIDI Agent 예시 프롬프트(코드·멜로디·베이스·드럼 네 문장)를 넣어 같은 요청에 대한 결과를 비교 기준으로 삼는다 | C |
