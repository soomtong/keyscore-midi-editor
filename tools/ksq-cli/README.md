# ksq-cli

`.ksq` 프로젝트와 계이름 텍스트(REQ 5.14)를 오가는 명령줄 도구와, 프롬프트 실험실 번들 픽스처 8곡(AI-18)의 생성기.

## 명령

~~~
ksq check <파일.ksq|.ksqz>...        # 불변식·형식 버전 검사. 하나라도 실패하면 종료 코드 1
ksq fixtures <디렉터리>               # 번들 픽스처 8곡을 .ksq로 쓴다
ksq2txt <입력.ksq> [-o 출력.txt] [--max-output <바이트>]   # 프로젝트 → 계이름 텍스트. 잃는 정보는 표준 오류에 한 줄씩
txt2ksq <입력.txt> [-o 출력.ksq] [--strict]   # 텍스트 → 프로젝트. 기본은 느슨 모드, .ksqz면 gzip
~~~

- 결과는 표준 출력(또는 `-o`)에, 경고·손실·오류는 표준 오류에 쓴다.
- 종료 코드: 0 성공, 1 실패, 2 잘못된 사용법.
- `-o`가 입력과 같은 파일(심볼릭 링크·하드 링크 포함)이면 거부한다.
- 새 형식 버전 파일은 앱이 경고와 함께 열지만, `ksq check`는 실패로 본다.
- `ksq2txt`는 텍스트가 상한을 넘을 것이면(먼 틱의 클립 등) 만들기 전에 거부한다. 크기는 만들기 전에 확실한 위쪽 한계로 어림한다(성부 수 ≤ 사건 수 + 1, 성부마다 클립 끝까지의 쉼표). 그래서 노트가 촘촘한 아주 긴 곡(4분음표 트랙이면 약 1,400마디부터)은 실제로는 작아도 거부될 수 있다. 그때는 `ksq2txt --max-output <바이트>`로 상한을 바꾼다(0은 오류, 상한을 사실상 없애려면 큰 수를 준다). 거부 메시지는 그 실행의 어림 값을 「`--max-output <어림 바이트>` 이상을 주면 크기 검사를 통과한다」 꼴로 안내한다. 큰 상한을 주면 도구는 실제로 그만큼 큰 텍스트를 만들 수 있다(어림은 위쪽 한계라 실제는 대개 훨씬 작지만, 메모리와 디스크를 그만큼 쓸 각오로 준다). 예외로, 어림이 u64 범위를 넘으면(u64 끝 근처 틱의 클립 등) 어떤 상한으로도 변환할 수 없으므로 안내 대신 그렇다고 알린다. 상한은 「텍스트가 나르는 내용만으로 다시 만든 프로젝트」의 정규 `.ksq` 바이트의 256배다. 입력이 `.ksq`든 `.ksqz`든 같고, 모르는 키·벨로시티처럼 텍스트로 가지 않는 것이나 압축으로는 상한을 키울 수도, 압축 때문에 거부될 수도 없다. 되읽은 결과가 손실로 설명되지 않게 다르면(`Loss::Mismatch`) 출력을 쓰지 않는다. 둘 다 종료 코드 1.

## `-o` 쓰기

두 바이너리의 `-o`는 같은 규칙을 따른다(`docs/decisions/2026-10-14-ksq-cli-output-path-scope.md`). `-o`는 「없는 경로」와 「일반 파일」만 받는다.

- 쓰기 전에(변환하기 전에) 대상을 링크를 따라가며 확인한다(`fs::metadata`, 경로 풀이는 커널이 한다).
  - 없으면(`NotFound`) 새로 만든다. 없는 디렉터리 안이면 만들 때 실패한다.
  - 일반 파일이면 같은 디렉터리의 임시 파일에 쓰고 fsync한 뒤 이름을 바꾼다. 쓰다 실패해도 기존 출력이 잘린 채 남지 않고, 임시 파일은 지운다. `txt2ksq`는 core의 `ksq::write_file`, `ksq2txt`는 이 crate의 `cli.rs`가 같은 방식을 쓴다.
    - 이름 바꾸기라서: 읽기 전용(0444) 출력 파일도 덮어쓰고(권한은 유지), 읽기 전용 디렉터리 안에서는 그 안의 파일이 쓰기 가능해도 실패하며, 하드 링크는 끊긴다(출력 경로만 새 내용을 가리킨다).
    - 심볼릭 링크는 링크를 일반 파일로 바꾸지 않고 대상 파일을 바꾼다. 대상이 없는 링크는 대상 경로에 만든다.
  - 그 밖은 모두 대상을 건드리지 않고 종료 코드 1로 끝난다.
    - 디렉터리, FIFO, 소켓, 장치(`/dev/null`, `/dev/stdout`, `/dev/fd/N` 포함).
    - `NotFound`가 아닌 확인 오류: 커널 한도를 넘는 링크 사슬(ELOOP), 권한 없음(EACCES), 끝이 `/`·`/.`인 일반 파일·장치 경로(ENOTDIR) 등.
- 장치나 파이프로 내보내려면 `-o` 없이 실행하고 셸로 리다이렉트한다. 예: `ksq2txt in.ksq > /dev/null`, `ksq2txt in.ksq | less`, `txt2ksq in.txt > out.ksq`. 거부 메시지도 그 바이너리에 맞는 예로 이렇게 안내한다. 확인 때 없던 대상을 만들지 못한 실패(없는 디렉터리 안, `/dev/<없는 이름>`, 끝 `/` 등)에도 같은 안내를 붙인다.
- 확인과 쓰기 사이에 다른 프로세스가 대상을 일반 파일이 아닌 것으로 바꾸면, 이름 바꾸기가 그것을 일반 파일로 바꿀 수 있다. 출력 디렉터리를 다른 주체와 나눠 쓰지 않는 개발 도구라 받아들인다.

원자적 쓰기 코드(`write_then_rename`·`resolve_symlink`·`temp_path`)는 core `ksq.rs`의 것을 거의 그대로 옮겨 왔다. core는 `.ksq` 프로젝트만 쓰는 공개 API를 내주고, 바이트를 받는 원자적 쓰기는 공개하지 않기 때문이다(core 공개 API 변경은 이 Task 범위 밖). 한쪽 보장을 고치면 다른 쪽도 함께 고쳐야 한다.

## 공개 API

- `check(path) -> Result<CheckReport, CliError>`
- `project_to_text(&Project) -> Result<(String, Vec<Loss>), CliError>`: 헤더는 틱 0의 템포·박자표와 조. 트랙마다 클립을 시작 0 클립 하나로 합친다. 쓴 텍스트를 다시 읽어 대조한다.
- `text_to_project(&str, Mode) -> Result<(Project, Vec<Diagnostic>), CliError>`: 블록마다 트랙 하나와 시작 0 클립 하나. 트랙 색은 순번대로 팔레트를 돈다.
- `fixtures()`, `write_fixtures(dir)`: 픽스처 8곡.
- `cli::{ksq, ksq2txt, txt2ksq}`: 바이너리 본체.

## 불변식

- 내부 의존은 `keyscore-core`와 `keyscore-text`뿐이다(`scripts/check-deps.sh`).
- `Loss`가 비어 있으면 `ksq2txt → txt2ksq` 결과의 `.ksq`가 원본과 바이트까지 같다.
- 픽스처는 `fixtures-src/*.txt`(엄격 모드로 읽히는 손으로 쓴 원곡)에서 만들고, `assets/fixtures/*.ksq`는 생성기 결과와 바이트까지 같다. 원본 텍스트를 고치면 다시 만든다.

~~~
cargo run -p ksq-cli --bin ksq -- fixtures assets/fixtures
~~~
